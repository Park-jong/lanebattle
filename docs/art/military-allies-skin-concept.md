## 목적과 적용 범위

기존 횡스크롤 라인 디펜스의 전투·성장 구조 위에 현대 밀리터리 대 좀비 테마를 입힌다. 플레이어 영웅 시온 1종과 기존 아군 10종·일반 적 10종·보스 5종을 대응시키고, 같은 테마로 플레이하는 데 필요한 기지·배경·UI·효과·사운드를 함께 준비한다.

이 문서의 캐릭터 표는 외형과 역할의 기준이다. 실제 공격 유형·태그·약점·비용·재소환·스킬 수치는 현재 게임 데이터를 우선한다. 의상이나 무기의 생김새만으로 새 판정, 탄약 소모, 재장전, 조준 조작을 추가하지 않는다. 히바리의 지상화처럼 실제 규칙이 달라지는 부분은 아래 별도 적용 항목으로 관리한다.

관련 기준: [게임 설계](../design.md) · [스킨·애니메이션 구조](../skins-and-animation.md) · [기본 아트 규격](default/README.md) · [기지 표시 규격](default/bases.md).

파일·이벤트 연결에는 기존 구조를 참고하되, 이번 테마의 인체 비율·원화 크기·화면 표시 크기는 아래의 일반 등신 규격을 우선한다.

개별 제작 문서: [밀리터리 26종 목록](military/README.md). 영웅·아군·일반 적·보스별 외형·팔레트·무기·모션·효과 파일·검수 기준을 분리했다. 기존 대상 ID를 파일명으로 사용하며 통합 설정의 인물 정보와 전투 대응을 유지한다.

이미지 제작 프롬프트: [전체 목록·사용 순서](military/prompts/README.md) · [JSON 작업 목록](military/prompts/jobs.json). 생성 예정 파일별 프롬프트와 참조 관계를 기록했으며 실제 이미지 생성·적용은 별도 단계다.

## 공통 컨셉

현대 밀리터리 × 일본 서브컬처 미소녀 × 성인 게임.

**이번 스킨은 머리부터 발끝까지 전신 비율을 살린 일반 등신 캐릭터로 제작한다.** 전투 스프라이트·미리보기·영웅·직접 통제 외형에 같은 비율을 적용한다. SD·치비 체형, 큰 머리와 짧은 팔다리, 전투용으로 별도 축약한 인체 비율은 사용하지 않는다. 얼굴을 확대하는 UI 아이콘은 같은 캐릭터 원화에서 구도를 달리한다.

아군 인체는 약 7~8등신을 제작 기준안으로 삼고, 성인 체형·어깨·골반·팔다리 길이·무릎과 발목의 구조를 유지한다. 캐릭터별 키와 체형 차이는 실제 비율로 표현한다. 적의 인간형 감염자도 일반 성인 비율을 바탕으로 하며, 스토커의 긴 팔다리·그로워의 비대화·보스의 변형은 각 컨셉에 맞게 적용한다. 기계·비인간형 변이체에는 인체 등신을 강제하지 않는다.

아군은 전원 20세 이상의 성인 여성 군인이다. 교복풍 제복과 장교 제복을 기반으로 병과별 전술 장비와 무기를 차별화하며, 성인 게임의 방향성에 맞춰 의상 노출도와 체형을 다양하게 구성한다. 적군은 좀비·변이체와 감염 지역의 기계 병기로 구성한다.

- 아군 중 드론은 레이카만 사용한다.
- 히바리는 지상에서 운용하는 대공방어병이다.
- 후우카는 전자전 지원병이다.
- 영웅을 포함한 아군은 동작에 따른 바스트 모핑을 적용하되 AA인 아카네·히바리는 제외한다. 머리카락·의상·장비 끈의 보조 움직임은 두 캐릭터에도 적용한다.
- 이번 문서는 플레이어 영웅 1종, 소환 아군 10종, 일반 적 10종, 적 보스 5종, 총 26종의 신스킨 컨셉을 다룬다.

### 기본 전투·스킬

좌우 이동과 가까운 적에 대한 자동 근접 베기를 유지한다. 기본 베기는 단일 대상이며, 검의 잔상만으로 광역 피해·방어 파괴·화상·기절을 추가하지 않는다. 전투 불능 시 짧게 무릎을 꿇고 퇴장하며 기존 부활 대기 후 전진 지휘소 앞에서 재투입된다. 신체 재생이나 분신 소환으로 해석하지 않는다.

다음 수치는 `src/data/hero.ts`·`skills.ts`의 강화 전 기준을 옮긴 제작 참고값이다. 실제 툴팁과 효과는 현재 전투 데이터를 사용한다. 충격파·의료 미스트·축전 모듈은 기존 효과를 설명하는 장비 설정이며, 새 자원이나 탄약 소모를 만들지 않는다.

## 캐릭터 설정 유지 기준

- 아군은 전원 성인 여성 군인이라는 설정과 각 캐릭터의 나이·키·체형 정보를 유지한다.
- 캐릭터별 머리색, 헤어스타일, 제복 실루엣, 주무기로 병과를 구별한다.
- 아군의 드론 및 무인기 연출은 레이카에 한정한다. 히바리는 지상 대공 요격 장비, 후우카는 전파 교란·통신·EMP 장비로 표현한다. 적군의 호버는 무인 공격 드론, 오버로드는 감염체와 기계가 융합된 공중 전투 병기로 표현한다.
- 후우카의 공격 타입 표기인 `마법·원거리`는 유지하고, 외형과 효과는 전자전 장비 중심으로 해석한다.
- 일반 적과 보스는 표에 명시한 기존 이름과 신규 이름의 대응을 유지한다.
- 캐릭터의 신체 치수는 원화 제작 참고 정보다. 전투 능력치·충돌 크기·카메라 배율·UI 수치로 사용하지 않는다.

## 전장·기지·자원·화면 문구

### 테마 용어

아래는 신규 테마의 표시명 제안이다. 내부 키와 저장 필드는 유지하며 테마별 문구 사전으로 변환한다. 획득량·용도·최댓값·소모량·해금 조건은 원래 기능을 따른다.

| 기존 표시 | 신규 표시 | 용도 |
| --- | --- | --- |
| 부적 | 보급 포인트 | 아군 소환·보급 강화 |
| 신력 | 지휘 에너지 | 영웅·직접 통제 스킬 |
| 기운 모으기 | 보급망 강화 | 소환 자원 충전·최대 보유량 강화 |
| 신명 | 작전 공로 | 기존 판 밖 성장 재화 |
| 엽전 | 크레딧 | 클리어 보상·성장 재화 구매에 쓰는 기존 판 밖 통화 |

기동 태그는 지상·공중 유닛 모두 가질 수 있다. 태그 아이콘과 비행 아이콘을 분리한다. 성장 노드·시너지·빙의 스킬·보스 약점 칩·오류 안내·로딩·결과 화면까지 동일한 이름을 사용한다. 툴팁 수치는 현재 강화가 적용된 데이터에서 생성하고 고정 문자열로 다시 작성하지 않는다.

### 5장 배경·기지 구성 제안

| 장 | 전장 배경 | 아군 전진 지휘소 | 적 감염 거점 | 보스 |
| --- | --- | --- | --- | --- |
| 1 | 봉쇄된 도심 외곽 | 임시 검문 지휘소 | 감염 둥지 | 하이브 마더 |
| 2 | 점거된 군사기지 | 장갑 방호 진지 | 장갑 격납고 | 저거너트 |
| 3 | 과열된 산업단지 | 냉각 보급 진지 | 용광로 제어동 | 멜트다운 |
| 4 | 폐쇄된 항공시설 | 대공 통제 진지 | 오염 관제탑 | 오버로드 |
| 5 | 변이 실험시설 | 최종 작전 지휘소 | 중앙 배양시설 | 타이런트 |

기존 5장·25스테이지의 순서, 웨이브, 보스 출현 시각, 승패·별 평가 규칙은 유지한다. 장별 기본 기지에 관문별 소품·색 변형을 조합하고, 25개 구조물을 모두 별도 원화로 만들지는 않는다. 현재 기지는 `BaseRenderer`의 코드 그래픽이므로 PNG만 납품하면 바로 교체되는 구조는 아니다. 신규 테마용 코드 외형 또는 별도 이미지 연결이 필요하다.

기지는 현재 표시 영역인 아군 196×166, 일반 적 212×180, 보스 관문 228×190을 기준으로 제작한다. 정상, 체력 66% 이하, 33% 이하, 파괴의 네 상태를 구별한다. 보스 생존으로 기지가 무적인 경우에는 별도 잠금·방호 표시를 사용한다. 기지 파손·잠금·큰 외형은 전투 목표 좌표·충돌·체력·적 출현 위치를 바꾸지 않는다.

전장에는 기존처럼 약간 내려다보는 넓은 길을 두고 지면의 앞뒤 경계를 보여 준다. 엄폐물은 배경 장식이며 새 엄폐·고저차·우회 레인 판정을 추가하지 않는다. 효과는 캐릭터 발 위치·비행 고도와 같은 좌표 변환을 사용한다.

### UI 제작 범위

960×540 기준 화면과 현재 버튼·단축키 구성을 따른다. 소환은 2줄×5칸, 이동은 좌우, 스킬은 Q/W/E를 유지한다. 기존 최소 터치 영역 66 게임 좌표를 줄이지 않는다.

| 전투 HUD | 자원 2종·보급 강화·소환 10종·스킬 3종 아이콘, 쿨타임·비용 부족·인원 상한·기지 체력 |

## 이미지·애니메이션 납품 규격

### 본체와 공통 파일

일반 아군·인간형 적·영웅은 768×1024, 대형 변이체·보스는 1536×1536을 작업용 캔버스 기본값으로 제안한다. 세로로 긴 보스는 1152×1536을 사용할 수 있다. 무기 휘두르기·레이카 편대처럼 가로 공간이 필요한 경우 가로폭을 늘려 종류별로 확정하되, 같은 종류의 모든 본체 동작은 가장 넓은 포즈를 포함하는 동일 캔버스·배율·기준점을 사용한다. 캔버스에 맞추기 위해 머리·몸통·다리 비율을 변형하거나 동작마다 인물 크기를 바꾸지 않는다.

| 항목 | 제작 기준 |
| --- | --- |
| 이미지 | 투명 RGBA PNG, sRGB. 본체에 배경·이름·체력바·그림자·큰 효과를 합성하지 않는다 |
| 원본 방향 | 오른쪽. 실제 진영·공격 방향에 따라 좌우 반전한다. 읽을 수 있는 문자·계급 텍스트를 본체에 넣지 않는다 |
| 지상 기준점 | 정규화 `(0.5, 0.875)`, 발 접점 중앙 |
| 비행 기준점 | 정규화 `(0.5, 0.5)`, 편대 또는 본체 중심. 비행 고도는 게임이 적용한다 |
| 오버로드 | 공중·착지 모두 같은 중심 기준점. 착지 포즈의 바닥을 기준점에 맞춘다 |
| 몸체 크기 | `bodyBounds`, `bodyWidth`, `bodyHeight`로 몸체를 명시한다. 무기·편대·망토 여백을 충돌 크기로 사용하지 않는다 |
| 화면 표시 크기 | 이번 테마 전용 `displayHeight`·`displayTop`을 설정한다. 사람은 전신이 읽히는 높이를 확보하며 기존 작은 동물 스프라이트 높이를 그대로 계승하지 않는다. 아래 표시 크기 기준안을 실제 화면에서 검증한다 |
| 미리보기 | `preview.png`, 1024×1024, 머리부터 신발까지 포함한 대표 전신. 세로 비율을 유지해 여백으로 맞추고 팔다리를 자르거나 눌러 넣지 않는다 |
| 아이콘 | `icon.png`, 128×128, 얼굴·병과 장비 중심. 작은 크기에서도 다른 슬롯과 구별한다 |
| 메타데이터 | `skin.json`: 캔버스, 기준점, 몸체 경계, 클립·fps·루프, 필요 시 표시 높이·상단 범위 |

### 전신 비율과 화면 가독성

- 아군의 최종 화면상 몸체 높이는 **169cm 캐릭터를 110 게임 좌표**로 두는 기준안을 먼저 시험한다. 다른 아군은 `110 × 캐릭터 키 / 169`로 키 차이를 유지한다. 이는 무기·머리 장식·드론을 제외한 머리부터 발바닥까지의 높이이며, 웅크리거나 공격할 때에는 자세에 따라 자연스럽게 달라진다.
- 위 높이는 `BATTLEFIELD.unitScale`까지 적용된 최종 표시 크기다. `displayHeight`에 같은 값을 넣고 배율을 다시 곱해 중복 확대하지 않도록 계산한다. 최종 수치는 실제 전투·휴대폰 가로 화면 검수 후 확정한다.
- 원화의 키 차이는 공통 인체 배율과 메타데이터로 재현한다. 모든 캐릭터의 머리를 같은 높이에 맞추거나, 방패병·해머병이라는 이유로 신체 전체를 임의로 확대하지 않는다. 방호력과 공격 범위는 장비 실루엣·UI로 구별한다.
- 기존 `width`·`height` 등의 전투 수치는 유지하고 표시 크기를 분리한다. 긴 다리·총신·해머·방패가 보이는 범위와 실제 공격 사거리·피격 판정을 혼동하게 하는 연출은 피한다.
- 일반 등신은 머리와 얼굴의 화면 점유율이 작으므로 머리색·헤어스타일·어깨 장비·주무기로 병과를 식별한다. 외곽선과 명암은 축소 시 형태가 남도록 정리하고 작은 문양·봉제선에 식별을 의존하지 않는다.
- 발의 앞뒤 배치와 깊이 정렬을 유지하고 전열·후열이 겹쳐도 상체·무기·체력바를 구별할 수 있게 한다. 혼잡을 줄이기 위해 인체를 SD로 바꾸거나 실제 개체 수를 줄이지 않는다. 필요하면 테마의 표시 배율·상태 아이콘 위치·효과 투명도를 조정한다.
- 걷기·돌진·타격은 골반·무릎·발목의 체중 이동이 이어지게 그린다. 짧은 다리의 통통 뛰는 이동을 기본 동작으로 사용하지 않는다. 무기 반동·의족 추진·방패 지지 자세는 각 장비의 구조를 따른다.
- 세로로 커진 본체가 하단 HUD·상단 경고·보스 체력바를 가리지 않도록 확인한다. 비행 편대는 인물과 드론을 포함한 전체 표시 영역을 점검하고, 보스 크기는 일반 성인 유닛과의 상대 크기로 검증한다.

### 바스트 모핑·머리카락·의상 보조 움직임

몸의 움직임에 뒤따르는 관성과 감쇠를 공통 애니메이션 방향으로 한다. 보행·가속·정지·베기·사격 반동에서 본체가 먼저 움직이고, 머리카락·의상과 적용 대상의 가슴이 조금 늦게 따라온 뒤 안정된다. 단순히 캐릭터 전체를 위아래로 흔들거나 모든 부위를 같은 주기로 반복하는 방식으로 대신하지 않는다. 모든 동작에서 일반 등신·관절 위치·몸체 체적을 유지한다.

#### 바스트 모핑 적용 대상

영웅 시온을 포함한 아군 11종 중 **9종 적용, AA 2종 제외**다. 적·보스에는 이 규칙을 자동 적용하지 않는다. 모핑은 제복을 착용한 상태의 형태 변화와 보조 움직임으로 제작하고, 의상·방호 장비의 고정 정도에 맞춰 움직임을 제한한다.

#### 머리카락·의상·장비

- 머리카락은 두피·묶은 지점이 머리 움직임을 따르고 중간 길이·끝부분이 순차적으로 따라오게 한다. 트윈테일·포니테일은 묶은 위치를 고정하고, 긴 머리는 어깨·등·무기와의 겹침을 관리한다. 숏컷·보브컷도 앞머리·옆머리·끝부분에 작은 지연을 둔다.
- 아카네·히바리의 트윈테일, 미카·시온의 포니테일, 아오이·쿠레하·세이라·레이카·후우카의 긴 머리, 하야테·쿠로가네의 짧은 머리를 각각 다른 무게·길이로 표현한다. 모든 캐릭터에 같은 머리카락 루프를 복사하지 않는다.
- 넥타이·재킷 자락·스커트 주름·코트·시온의 짧은 망토는 부착점에서 멀수록 늦게 반응한다. 의복의 봉제·고정 부위를 유지하고 동작마다 옷 길이·형태가 달라지지 않게 한다.
- 홀스터·탄약 파우치·방탄 조끼·건틀릿 같은 단단한 장비는 몸에 고정한다. 끈·케이블만 작은 흔들림을 허용하고 총기·칼날·방패 전체를 고무처럼 변형하지 않는다.
- 레이카 편대의 비행은 가벼운 기울기·고도 변화에 따른 반응으로 표현한다. 다른 지상 캐릭터에게 같은 공중 부유 루프를 적용하지 않는다.
- 환경 바람은 자세에 작은 변화를 더하는 연출로만 사용한다. 정지 중 머리카락이 항상 한쪽으로 크게 펄럭이거나 실내·실외 모두 같은 강풍이 부는 표현을 기본으로 하지 않는다.

#### 제작·연결 방식

현재 PNG 아틀라스 렌더러에는 신체·머리카락·의상별 런타임 물리나 메시 모핑 기능이 없다. **1차 구현은 제작 단계에서 보조 움직임을 넣고 프레임 PNG로 출력하는 방식**으로 한다. 프레임마다 별도로 캐릭터를 다시 그리기보다 같은 기준 원화·레이어·리깅을 사용해 얼굴·체형·제복의 연속성을 유지한다.

아래 공통 19컷은 기본 동작의 최소 목록이다. 모핑·머리카락 관성·이동과 정지의 전환이 끊기지 않도록 필요한 클립의 중간 프레임과 전환 프레임을 추가한다. 특히 대기 2컷·이동 4컷만으로 최종 품질을 충족했다고 보지 않는다. 추가 프레임 수·fps·루프는 대표 캐릭터 검수 후 확정하고 `skin.json`과 실제 manifest에 반영한다. 프레임이 늘어도 기존 공격 판정 시점·이동 속도·스킬 쿨타임은 유지한다.

멈춤·방향 전환·행동 간 블렌딩이 필요한 경우 별도 클립과 렌더러 전환 처리를 함께 추가한다. PNG 파일명이나 메타데이터만 추가해도 자동으로 보간되는 것으로 취급하지 않는다. 추후 실시간 메시·본 기반 모핑을 채택하면 부위 분리 원화·가중치·물리 파라미터와 렌더러 연동을 별도 제작 범위로 산정한다.

각 캐릭터마다 모핑 적용 여부, 보조 움직임 대상 부위, 의상 고정 영역, 클립별 강도·안정화 구간을 제작용 메타데이터로 기록한다. 이 정보는 현재 런타임에서 자동 처리되는 필드가 아니다. 일시정지·결과 화면에서는 모든 보조 움직임도 멈추고, 재개·새 전투·직접 통제 외형 변경 때 튀거나 이전 상태가 남지 않도록 한다. 정적 아이콘·`preview.png`는 정적 이미지로 유지하고 애니메이션 미리보기가 필요하면 별도 UI로 재생한다.

파일 확장자는 `.png`, 아틀라스 프레임 키는 확장자를 뺀 이름이다. 기본 본체는 종류별 최소 19컷이다. 소환 아군·적·보스 25종은 본체 475장·아이콘 25장·미리보기 25장, 시온까지 26종은 본체 494장·아이콘 26장·미리보기 26장이다. 여기에 시온 전용 스킬 포즈·효과 24장을 추가한 **570장은 최소 산정량**이다. 자연스러운 모핑·머리카락·의상 동작을 위한 중간·전환 프레임, 나머지 고유 동작·투사체·공통 효과는 별도 산정하고 재사용한다.

그로워는 기존 성장 상태의 배율을 사용하므로 성장 단계마다 본체 19컷을 다시 만들지 않는다. 큰 무기·짧은 치마·머리카락·의족은 대기부터 퇴장까지 일관된 형태를 유지한다. 원화 상세 묘사보다 실제 전투 크기에서 머리색·병과 무기·실루엣을 먼저 확인한다.

현재 렌더러는 발사자 클립 중 첫 `projectile_*`를 사용한다. 1차 연결은 종류별 대표 투사체 1개로 제한하고, 탄종·무기별 선택이 필요하면 렌더러를 확장한다. 손·총구·발사관 부착점은 후속 확장용 납품 정보이며 현재 코드는 몸체 높이를 기준으로 발사 좌표를 계산한다.

추가 `grab`, `summon`, `suppress`, `descend` 등의 클립 이름만 등록해도 자동 재생되지는 않는다. 기본 공격·현재 상태 표시를 먼저 연결하고, 고유 동작은 실제 전투 이벤트에 맞춘 호출 작업을 별도로 한다. 영웅의 `skill_fan`, `skill_blessing`, `skill_blade` 및 대응 `fx_*`, 오버로드의 `ground_idle`은 현재 렌더러 연결점을 활용한다.

## 테마 로딩·파일 구조·저장

현재 `artFor()`는 `subjectKey`의 첫 항목을 조회하며 스킨 ID로 선택하지 않는다. `BootScene`은 단일 `manifest.json`을 읽고, 패킹 스크립트는 `default`와 기존 텍스처명을 사용한다. 신규 이미지 폴더만 추가하면 테마를 전환할 수 있는 상태가 아니다.

구현 방향은 전투 진입 전에 테마를 선택하고, 선택된 테마 전용 manifest를 읽는 방식으로 한다. 전투 중 변경은 1차 범위에서 제외한다. 현재 기본 manifest는 유지하고 신규 테마 경로·패킹 옵션·표시 문구·기지 외형을 함께 분기한다.

```text
output/art-generation/source-assets/<ally|enemy|boss>/<기존ID>/military/
  skin.json
  idle_00.png ... death_03.png
  icon.png
  preview.png
  ...필요한 투사체·효과...

public/assets/characters/themes/military/manifest.json
public/assets/characters/runtime/military/<분류>-<기존ID>.png
public/assets/characters/runtime/military/<분류>-<기존ID>.json
```

위 경로는 신규 테마용 제안이며 현재 패커가 지원하는 경로는 아니다. 시온 원본은 같은 구조의 `hero/kkomaMudang/military/`에 둔다. 패킹 단계에서 기존 원본 보관본과 기본 배포 아틀라스를 덮어쓰지 않도록 출력 경로를 분리한다.

- manifest의 `subjectKey`는 기존 키, `skinId`는 `military`, `texture`는 `military-ally-clubGoblin`처럼 테마 접두사를 사용한다. 테마 manifest 내부에서는 대상 키당 한 항목만 둔다.
- `image`·`atlas`는 기존 `assets/characters/`를 기준으로 한 상대 경로다. 배포 하위 경로에서도 `BASE_URL`을 통해 로드한다.
- 원본 크기와 런타임 크기를 구분한다. 현재 패커 기본 본체 최대 변은 일반 유닛 96px·영웅 128px·보스 192px이며, 아이콘 96px·미리보기 192px로 축소한다. 이번 테마는 일반 등신의 얼굴·손·장비를 보존하도록 본체 `runtimeLimit`을 일반 유닛 256px·영웅 320px·보스 512px부터 검토한다. 원본을 키워도 기존 축소 한도를 그대로 사용하면 세부 표현이 남지 않는다.
- 위 런타임 크기는 확정값이 아니다. 기본 테마와 분리해 실제 표시 크기·메모리·로딩 시간을 측정하고 정한다. 현재 패커의 아틀라스 폭 1024px·높이 상한 2048px에 전체 프레임이 들어가는지 확인하며, 초과하면 신규 테마 패커의 배치·크기 또는 아틀라스 분할과 로더 연결을 조정한다. 미리보기의 런타임 축소 한도도 전신 열람 용도에 맞춰 별도로 검토한다.
- UI와 전투가 같은 테마의 manifest를 사용하게 한다. `icon`, `preview` 프레임도 아틀라스에 포함한다.
- 이름·병과·자원·공격 유형·특성·스킬·성장 노드 문구는 테마별 표시 계층으로 관리한다. 기존 전투 데이터의 `name`을 일괄 변경해 기본 테마 문구까지 바꾸지 않는다.
- 선택 테마는 별도 설정으로 저장하고 기존 진행·강화·빙의 해금 ID는 유지한다. 히바리 지상화를 적용할 때는 테마별 전투 정의도 함께 선택하고 저장된 테마가 없는 기존 세이브는 기본 테마로 연다.
- 이미지·프레임 누락 시 기존 도형·텍스트 표시와 대기 클립 대체를 유지한다. 미완성 테마는 개발 확인용으로 두고 완성 테마 선택 목록에는 노출하지 않는다.
- 제작 파일에는 제작자·도구·제작일·원본·수정 이력·이용 조건을 기록한다. 원본 보관 파일은 배포에 포함하지 않는다.

## 사운드 제작 범위

필수 기능음은 진압봉·단검·격투·해머·방패 타격, 소총·유탄·미사일·드론 사격, EMP, 감염액, 회복·강화·억제, 소환·퇴장, 보스 등장·강하, 기지 피격·파괴, UI 선택·실패·강화다. 각 캐릭터 전용 보이스는 후속 범위로 두고 우선 공통 기능음으로 플레이를 확인한다.

같은 순간 여러 유닛이 공격해도 총성·경고음이 과도하게 겹치지 않도록 같은 효과음의 동시 재생 수와 재생 간격을 제한한다. 보스 경고·자원 부족·스킬 준비 정보는 소리 없이도 화면으로 확인할 수 있어야 한다. 효과음·배경음 설정과 일시정지 동작은 기존 옵션을 따른다.

## 제작 순서와 완료 기준

1. **적용 설계**: 히바리 지상화의 실제 규칙과 검증 범위, 레이카 공중 편대 표현, 시온의 보행·세이버·스킬 연결을 정리한다. 테마 분기와 문구 사전 구조를 준비한다.
2. **대표 제작**: 시온·아카네·아오이·레이카·히바리·워커·그로워·오버로드의 일반 등신 기준 원화와 기본 이동·아이콘부터 준비한다. 시온·아카네·쿠레하를 모핑 적용·제외 및 체형별 비교 대상으로, 미카를 포니테일 동작 비교 대상으로 추가 검수한다. 대기·이동·정지·공격에서 필요한 중간·전환 프레임 수를 정한다.
3. **연결 검증**: 개발용 테마 manifest와 기본 기지·HUD로 실제 화면 크기, 좌우 반전, 발 위치, 비행 높이, 투사체·체력바 좌표를 확인한다. 다수 유닛이 겹친 전투와 휴대폰 가로 화면에서 전신 실루엣·무기·얼굴 식별을 확인한 뒤 표시 배율·런타임 해상도를 확정한다.
4. **전투 에셋 확장**: 아군 10종·적 10종·보스 5종의 기본 19컷과 대표 투사체·상태 효과를 완성하고 강화·직접 통제 스킬을 점검한다.
5. **전체 테마 완성**: 영웅, 5장 배경·기지, UI·문구·사운드를 연결한다. 같은 화면에서 기본 테마와 신규 테마 요소가 의도치 않게 섞이지 않는지 확인한다.
6. **선택 기능 공개**: 아래 검수를 통과하면 사용자용 테마 선택·설정 저장을 연결한다. 진행 저장은 기존 빌드와 호환되게 유지한다.

- [ ] 시온의 기본 베기와 Q/W/E, 강화 분기, 재투입, 직접 통제 외형이 기존 전투 기능과 일치하고 W/E의 원형 효과가 실제 범위를 표시한다.
