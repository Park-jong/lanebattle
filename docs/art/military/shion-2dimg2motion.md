# 시온 기본 공격 — 2dimg2motion 시험 적용

적용일: 2026-11-06. 밀리터리 스킨의 시온 기본 공격을 기존 개별 포즈 6장에서 14프레임 시퀀스로 교체하고, 이후 걷기도 8장에서 양발이 교대하는 12프레임으로 교체했다. 대기·피격·스킬·아이콘은 기존 v2 프레임을 사용한다. 아래 첫 부분은 공격 제작 기록이며 걷기 기록은 마지막 절에 있다.

## 생성 방식

[2dimg2motion](https://github.com/WU-HAOTIAN34/2dimg2motion)의 기준 이미지 분석 → 외형·손·무기 고정 → 핵심 포즈 공동 생성 → 중간 프레임 생성 → 정렬·검수 절차를 적용했다. 핵심 포즈 02/05/08/11은 한 시트에서 함께 생성했고, 중간 프레임 01/03/04/06 및 07/09/10/12는 두 시트로 생성했다. 00/13은 같은 기준 이미지다.

모든 새 자세는 내장 `image_gen`이 캐릭터 전체를 다시 그렸다. Python은 거의 투명한 알파 잡음 정리, 셀 분리, 시퀀스 전체의 공통 배율 조정, 기준선 이동, 아틀라스·GIF 패킹만 수행한다. 포즈 합성·팔다리 회전·워핑·자동 중간 그림 생성은 사용하지 않았다. 배경은 생성 도구의 실제 투명 RGBA를 사용했다.

좌우 정렬은 검까지 포함한 그림 전체의 중앙 대신 두 부츠의 지지 중심을 기준으로 평행 이동한다. 긴 검이 좌우로 움직일 때 몸이 반대쪽으로 밀리는 현상을 방지하며, 프레임마다 캐릭터 배율을 따로 맞추지 않는다.

실제 프롬프트와 채택한 생성 파일 식별자는 [프롬프트 기록](prompts/shion-2dimg2motion-attack.json)에 있다. 검 끝이 셀에 너무 가까운 결과, 중간 시트의 배율이 다른 결과, 회복 시 검 끝이 지면을 뚫는 결과는 재생성했다.

## 게임 연결

아틀라스: `public/assets/characters/runtime/military/hero-kkomaMudang-military-motion-v1.{png,json}`. 밀리터리 목록에서 시온만 새 텍스처로 연결한다. 원래 v2 아틀라스도 보관한다.

현재 게임은 공격·걷기를 합친 `hero-kkomaMudang-military-motion-v2.{png,json}`를 사용한다. 총 86장·16클립이며 `motion-v1`은 공격만 교체했던 이력으로 보관한다.

공격 프레임: `attack_00`–`attack_13`. `contactFrame: 5`, 타격 유지 0.055초, 타격 이후 회복 0.32초, 다음 공격 전 준비 최대 0.20초다. 빨라진 공격 간격 안에 준비·회복 시간이 들어가도록 표시 시간만 줄인다.

전투 모델은 기존처럼 공격 이벤트와 동시에 피해를 처리하므로 해당 이벤트에서 05를 즉시 표시한다. 이후 06–13으로 회복한다. 첫 조우의 즉시 공격은 준비 동작을 생략한다. 이후에는 기존 쿨타임 끝부분에 유효한 지상 근접 대상이 있고 영웅이 멈춰 있으며 바라보는 방향이 맞을 때만 00–04를 표시한다. 이동·방향 변경·기절·대상 소멸·빙의 시에는 이 준비 표시를 적용하지 않는다. 공격 간격·피해·사거리·난수는 변경하지 않는다.

## 보관과 재패킹

기준 이미지·생성 원본·프레임·검수 결과: `output/art-generation/revisions/shion-2dimg2motion-attack/`.

- `delivery/`: 투명 PNG 14장, 핵심 PNG 4장, 스프라이트시트, 컨택트시트, 흰 배경 GIF, 명세.
- `comparison.gif`: 같은 0.6초 공격 주기의 기존/신규 비교. 준비 구간 뒤 0.20초에 공통 타격 시점을 둔 검수용 재생이다.
- `package/`: 기존 밀리터리 재패킹 스크립트가 우선 사용하는 새 시온 패키지.
- `runtime-frames/`: 게임에 연결된 256px 공격 셀.

재패킹은 `python scripts/package-shion-motion.py`로 한다. 기준 이미지와 채택한 생성 시트가 필요하다. `python scripts/pack-military-runtime.py`도 이 패키지가 있으면 새 공격을 유지한다. 생성 원본·검수 파일은 기존 저장소 규칙에 따라 Git과 배포에서 제외한다.

## 검증

2dimg2motion의 14프레임 검증기를 통과했다. 시작/끝 동일, 핵심 포즈 일치, RGBA·공통 크기·바닥선·흰 배경 GIF를 확인했다. 런타임 아틀라스의 프레임 참조와 경계는 프로젝트 테스트로 검사한다.

로컬 Chrome에서 실제 BattleScene의 연속 공격을 샘플링했다. 피해가 발생한 세 공격 모두 `attack_05`, 나머지 준비·회복 프레임도 재생됐다. 일시정지 시 프레임·표시 시계·피해가 함께 멈췄고, 왼쪽 이동 후 좌우 반전·사거리 이탈 후 대기 복귀를 확인했다. 브라우저 예외와 에셋 누락은 없었다. 보고서와 캡처는 `output/browser-check/`에 보관한다.

## 걷기 후속 적용

원본 기준 이미지를 참조해 00/03/06/09의 접지·통과·반대발 접지·통과 포즈를 한 시트에서 생성했다. 중간 01/02/04/05 및 07/08/10/11도 모델이 전체 캐릭터를 다시 그렸다. 처음 생성한 시트의 같은 다리 반복 오류는 허벅지 홀스터를 기준으로 수정했다. 12장 모두 서로 다른 자세이며 11에서 00으로 직접 연결한다. 반복 도중 대기 포즈를 끼우거나 마지막에 00을 중복하지 않는다.

걷기는 두 발이 번갈아 움직이므로 두 발의 중앙을 고정하지 않는다. 허리의 청록색 전원 모듈 위치를 기준으로 좌우 정렬하고, 디딤발 바닥선만 이동시킨다. 캐릭터마다 다른 배율을 적용하지 않고 전체 시트에 공통 배율을 사용해 통과 자세의 작은 상하 움직임을 남긴다. 공격 프레임과 나머지 셀은 픽셀 배열 비교로 보존을 확인한다.

`clips.walk.strideLength: 90`은 원본 픽셀 기준 한 주기의 지면 이동 거리다. 렌더러가 실제 이동 거리와 표시 배율로 걸음 위상을 계산한다. 이동 속도·저속 효과·표시 크기에 따라 보폭 재생이 맞춰지고, 정지·막힌 이동·일시정지에서는 위상이 진행되지 않는다. 기존 스킨은 기존 시간 기반 재생을 사용한다. 시작·정지·방향 전환 클립은 기존 것을 사용한다.

- 실제 프롬프트: [걷기 프롬프트 기록](prompts/shion-2dimg2motion-walk.json).
- 생성 시트·납품: `output/art-generation/revisions/shion-2dimg2motion-walk/`의 `sources/`, `delivery/`.
- 비교 GIF: 같은 주기 길이로 맞춘 `comparison.gif`. 게임의 실제 재생은 지면 이동 거리에 따른다.
- 걷기 재패킹: `python scripts/package-shion-walk.py`.
- 공격 재패킹도 걷기 원본이 있으면 뒤이어 걷기를 적용한다. 전체 밀리터리 재패킹은 걷기까지 합친 최신 패키지를 우선 사용한다.

Chrome의 실제 전투에서 12개 걷기 프레임 전부 재생, 좌우 이동·정지·일시정지·저속 효과를 확인했다. 프레임 위상이 나타내는 거리와 실제 이동 거리가 일치했고, 50% 저속 효과의 측정 이동량은 기본의 약 51%였다. 기존 공격도 다시 검수해 피해 시점이 계속 05 프레임과 일치함을 확인했다. `output/browser-check/shion-walk-verification.json`에 결과를 보관한다.
