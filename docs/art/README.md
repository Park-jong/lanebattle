# 캐릭터 이미지 제작 가이드와 전체 목록

작성일: 2026-11-04 · 상태: 아트 명세 및 기본 26종 생성 초안

**영웅 1종·아군 10종·일반 적 10종·보스 5종, 총 26종**의 개별 이미지 콘셉트와 파일 명세를 정리했다. 각 캐릭터에는 기본 스킨과 추가 스킨 콘셉트 2종을 제안한다. 이 폴더의 문서는 제작 지침이며 실제 PNG나 게임 기능이 완성되었다는 의미는 아니다.

[게임 전체 설계](../design.md) · [스킨 등록·선택 및 애니메이션 구조](../skins-and-animation.md)

기본 26종의 생성 이미지와 검증 범위는 [아트 생성 기록](GENERATED.md)에 정리했다. v0.8.0에서 전투와 소환·빌드·타이틀·보스 UI에 연결했으며, 개별 PNG·런타임 아틀라스·전체 미리보기 경로와 추가 검수 사항을 확인할 수 있다.

## 공통 아트 방향

세계는 **한국 민담을 재해석한 요괴 마을 축제**다. 꼬마 무당이 친근한 요괴와 함께 등불을 되찾으러 간다. 아군은 든든하고 장난스럽게, 적은 심술궂지만 놀라면 허둥대는 모습으로 그린다.

- 둥근 2D 카툰, 큰 실루엣, 굵고 일정한 먹색 외곽선, 큰 면 중심의 채색을 사용한다.
- 피부·나무·돌·천의 차이는 큰 색면과 한두 개의 특징으로 표현한다. 한지 질감은 아주 약하게 넣어 작은 화면에서 지저분해지지 않게 한다.
- 도깨비는 청, 불 계열은 적, 신수는 황, 바람은 백·하늘색, 적은 먹색·보라색을 기본으로 한다. 두 태그를 가진 아군은 두 계열을 섞는다.
- 영웅은 미색 소매·적색 옷깃·황색 부적으로 독립적인 시선을 받게 한다.
- 적의 미색·철색·갈색 몸에는 먹보라 그늘이나 천을 남겨 아군과 구분한다. 진영은 색뿐 아니라 체형·소품으로도 읽혀야 한다.
- 원화는 실제 전승의 외형을 고증한 도감이 아니라 **이 게임을 위한 창작 해석**이다. 개별 문서에 없는 설정을 역사·민속의 사실로 취급하지 않는다.
- 현재 전투 역할·공격 방식·비행 여부를 바꾸는 장식을 넣지 않는다. 기획하지 않은 무기나 날개를 추가하면 역할을 오해하게 된다.

게임의 일반 유닛은 약 20~52px 높이에서 보인다. 작은 문양보다 방망이·활·한 다리·뿔·머리장식처럼 큰 특징을 남긴다. 보스는 현재 약 90~150px 영역을 기준으로 삼는다.

## 납품 파일과 경로

기본 경로는 다음과 같다. 문서 파일은 이 폴더에 두고, 실제 이미지는 제작 후 아래 에셋 경로에 넣는다.

```text
public/assets/characters/<hero|ally|enemy|boss>/<종류ID>/<스킨ID>/
  idle_00.png
  idle_01.png
  walk_00.png ~ walk_03.png
  attack_00.png ~ attack_03.png
  hit_00.png ~ hit_01.png
  spawn_00.png ~ spawn_02.png
  death_00.png ~ death_03.png
  preview.png
  icon.png
  ...종류별 고유 동작 및 효과...
```

- 첫 스킨 ID는 `default`다. 추가 스킨은 같은 파일명을 사용하고 폴더만 별도 ID로 만든다.
- `~`는 파일명 일부가 아닌 연속 범위 표기다. 예를 들어 `walk_00.png ~ walk_03.png`는 4개 파일이다.
- 각 문서의 표는 프레임마다 필요한 자세를 순서대로 설명한다. 파일 순서와 설명 순서를 맞춘다.
- 본체는 스킨당 공통 19장이다: 대기 2 + 이동 4 + 공격 4 + 피격 2 + 소환 3 + 퇴장 4. 미리보기 1장과 아이콘 1장, 고유 효과는 별도다.
- 이 전체 목록은 최종 제작 범위다. **최초 준비는 종류별 기준 원화 `idle_00.png`와 이동 4장**부터 가능하다.
- 일반 PNG부터 시작할 수 있다. 아틀라스로 묶을 때 `atlas.png`, `atlas.json`을 출력하고 파일 확장자를 뺀 이름을 프레임 키로 유지한다.
- 부위별 종이 인형 원화를 추가할 경우 `parts/` 아래에 `body.png`, `head.png`, `arm_front.png`, `arm_back.png`, `weapon.png` 등을 두고 부착점 정보도 함께 납품한다. 이번 본체 프레임 목록과 중복 제작을 필수로 요구하지 않는다.

개별 문서의 추가 스킨은 제작 후보이며, 전부 즉시 그려야 한다는 요구는 아니다. 기본 외형을 먼저 확정한 뒤 같은 체형과 동작 규격으로 확장한다. 각성·정예·성장은 스킨 이름과 별개의 전투 상태로 처리한다.

## 이미지 규격과 기준점

| 항목 | 공통 규격 |
| --- | --- |
| 본체 파일 | 투명 RGBA PNG, sRGB, 한 파일에 한 캐릭터 포즈 |
| 캔버스 | 개별 문서의 지정 크기 사용. 같은 종류의 모든 본체·고유 포즈는 같은 크기 |
| 일반 본체 크기 | 256×320 / 320×320 / 384×320 / 320×384 등 체형에 맞춘 원화 크기 |
| 보스 본체 크기 | 640×640 / 768×640 / 640×768. 긴 소매·꼬리까지 여유 확보 |
| 지상 기준점 | 캔버스의 가로 50%, 세로 87.5%. 발·뿌리·몸 고리의 지면 접점 중앙 |
| 비행 기준점 | 캔버스 가로 50%, 세로 50%. 몸통 또는 편대의 중심. 비행 고도는 코드가 더함 |
| 방향 | 적도 원본은 오른쪽. 게임에서 왼쪽을 볼 때 좌우 반전 |
| 미리보기 | 512×512, 투명 배경, 대표 전신 포즈, 적당한 여백 |
| 아이콘 | 128×128, 투명 배경, 얼굴·소품 중심. 테두리·문자·수치는 UI에서 합성 |
| 일반 효과 | 각 표의 별도 크기 사용. 본체와 다른 에셋으로 분리 |
| 최종 확인 | 밝은 배경·어두운 배경·투명 체크판에서 외곽선과 알파 확인 |

지상과 비행의 기준점 좌표는 원화 납품 규칙이다. 실제 구현에서 Sprite origin이나 아틀라스 피벗으로 연결한다. 원화 캔버스 크기를 현재 게임의 폭·높이에 무조건 늘여 맞추지 말고, **몸체의 기준 실루엣**이 기존 크기에 대응하도록 균일 배율을 정한다. 무기·꼬리·소매가 들어갈 투명 여백은 충돌 크기가 아니다.

기본 원화에서 몸체 경계와 기준점을 별도 메타데이터에 기록해 같은 종류의 다른 스킨에도 적용한다. 검수용 가이드 선은 최종 PNG에 포함하지 않는다. 아틀라스에서 투명 영역을 잘랐다면 원본 크기와 잘린 오프셋을 보존한다.

비행 종류는 삼족오·까치 떼·일반 어둑시니와 비행 상태의 어둑시니 대왕이다. 지상·비행을 오가는 대왕은 **모든 본체 프레임의 캔버스 중심 기준점**을 공통으로 쓰고, 착지 포즈의 몸 바닥을 그 기준점에 맞춰 실제 고도 0에서 지면에 닿게 한다. 착지 포즈의 바닥 위치 때문에 다른 프레임의 origin을 갑자기 바꾸지 않는다.

영등 바람·처녀귀신·손각시는 가볍게 떠 보이는 재질이어도 현재 지상 이동 종류다. 별도 비행 고도를 주지 않는다. 해태·불가사리는 네 발, 외다리 도깨비는 한 다리, 삼족오는 세 발, 구미호는 아홉 꼬리를 유지한다.

## 동작 제작 규칙

- 이동 4장은 접지 → 체중 이동 → 반대 디딤 → 회복이 끊기지 않게 만든다. 한 다리·날갯짓·뱀 몸은 개별 명세의 주기를 따른다.
- 이동 루프의 마지막 그림은 첫 그림을 복사해 끼우지 않고 다음 디딤으로 이어지는 중간 자세로 만든다.
- 대기·이동·공격을 오가도 머리 크기, 몸통 비율, 소품 크기, 기준점을 유지한다.
- 기본 공격의 준비·타격·회수는 제작 순서다. 기존 즉시 판정을 유지하는 구현에서는 **타격·발사 자세를 실제 공격 순간에 맞추고 준비 포즈는 생략할 수 있다.** 새 준비 시간을 전투 규칙에 임의로 추가하지 않는다.
- 피격은 짧은 움찔이다. 쓰러짐·공격 취소·무적 시간은 원화만으로 새로 만들지 않는다. 공격 중에는 본체를 유지하고 별도 색 강조만 겹칠 수 있다.
- 적 퇴장은 겁먹거나 허둥대며 작은 안개로 사라지는 톤이다. 얼굴 없는 달걀귀신은 표정 대신 몸이 오므라드는 동작으로 표현한다.
- 소환·퇴장 원화에 다른 전투 개체를 합성하지 않는다. 광역 공격의 대상이나 소환 부하는 실제 개체로 별도 표시한다.
- 지면 그림자, 체력바, 이름, 숫자, 상태 아이콘, 큰 오라, 투사체는 본체 PNG에 넣지 않는다. 방울·손끝의 작은 빛 정도만 기준 원화에서 일관되게 허용한다.
- 원본 한 벌을 반전해서 쓸 수 있도록 부적·명부·장승에 읽을 수 있는 문자를 넣지 않는다. 대신 좌우 대칭의 매듭·점·기하 문양을 쓴다.
- 고유 동작 이름(`grab`, `grow`, `tail`, `suppress` 등)은 향후 렌더러 확장 명칭이다. 현재 엔진에 이미 구현된 클립이라고 가정하지 않는다.
- 보스 스킬의 시각 예고를 넣어도 실제 공격 시점·범위는 기존 패턴을 따른다. 시점 변경은 별도 전투 설계가 필요하다.

## 제작 순서와 검수

1. 개별 문서의 콘셉트·팔레트로 기본 대기 원화 1장을 확정한다.
2. 실제 게임 표시 크기로 축소하고, 오른쪽·왼쪽 반전 상태에서 실루엣을 확인한다.
3. 같은 원화를 기준으로 이동 프레임을 만든다. 매 장을 독립적으로 재해석해 새 캐릭터처럼 만들지 않는다.
4. 대표 종류로 게임 연결과 기준점을 검증한 뒤 공격·피격·소환·퇴장·고유 효과를 추가한다.
5. 기본 스킨이 안정되면 추가 스킨을 제작한다. 의상 변경 후에도 같은 대상임을 알아볼 수 있어야 한다.
6. 아래 납품 메타데이터와 함께 최종 검수한다.

우선 제작 묶음은 꼬마 무당 → 도깨비 방망이병 → 달걀귀신 → 삼족오 → 그슨대 → 어둑시니 대왕이다. 좌우 직접 이동·기본 전진·기본 적·비행·성장·착지 전환을 작은 묶음으로 확인할 수 있다. 이후 나머지 종류를 순차 제작한다.

납품 때 종류별로 캔버스, 기준점, 몸체 기준 경계, 프레임명과 순서, 권장 재생 속도, 효과 부착점(손·입·발)을 기록한다. 코드에서 실제 스킨 정의를 작성하기 전까지 이 문서의 값은 제작 제안이다.

출처·사용 조건은 종류·스킨별로 제작자 또는 도구명, 원본 출처, 이용 조건, 수정 내역, 생성·제작일을 기록한다. 직접 그린 원화와 생성 도구로 만든 이미지 모두 최종 파일에 어떤 원본이 쓰였는지 추적할 수 있게 한다.

## 설계 문서의 범위

- 개별 캐릭터 제작 문서 26개와 이 공통 가이드.
- 기본 스킨 이미지 파일별 자세·외형 설명과 고유 동작·효과 파일 제안.
- 캐릭터별 추가 스킨 콘셉트 2개씩, 총 52개 제안.
- 기본 26종의 이미지 생성·정리 결과는 [아트 생성 기록](GENERATED.md)에 있다. 추가 스킨과 게임 코드 연결은 별도 작업이다.
