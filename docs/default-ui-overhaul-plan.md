# 기본 스킨 게임 UI 대대적 개선 계획

작성일: 2026-11-05 · 상태: 기본 UI 개편 구현 및 브라우저 검증 완료

## 1. 목표와 적용 범위

기본 꼬마 무당·한국 민담 요괴 테마의 UI를 **한밤의 요괴 마을 축제**라는 하나의 시각 언어로 개편한다. 전투 중 판단에 필요한 정보가 먼저 보이고, 지도와 빌드 화면에서도 같은 버튼·색·서체 규칙을 사용하게 한다.

여기서 기본 스킨은 개별 캐릭터의 `default` 의상만이 아니라 `docs/art/default/`에 정의된 기본 세계관을 뜻한다. 적용 대상은 타이틀, 지도, 빌드, 전투 HUD, 툴팁, 일시정지, 결과, 설정, 로딩·화면 회전 안내다.

- 기본 캐릭터 26종의 원화·동작 컷은 재사용한다. 초상화 크롭·배치·UI 프레임을 개선한다.
- 전투 수치, 충돌 판정, 스킬 효과·범위·발동 시점, 소환 순서, 보상, 빌드 조건과 저장 데이터 의미를 유지한다.
- 상점, 신규 재화, 신규 성장 기능은 추가하지 않는다.
- 아래는 최초 개선 계획이며, 실제 적용 내용과 검증 결과는 9절에 기록한다.

## 2. 현재 상태와 개선 근거

아래 표는 개편 전 소스와 설계 문서를 기준으로 한 초기 진단이다. 내장 브라우저 연결 오류 이후 별도 로컬 Chrome에서 개편한 화면을 캡처하고 입력 동작을 검증했다.

| 영역 | 확인한 현재 구현 | 개선 과제 |
| --- | --- | --- |
| 전체 구조 | Phaser 캔버스 960×540, 메뉴·HUD 색상이 여러 씬에 직접 지정됨 | 기본 테마의 색·서체·여백·상태 표현을 일관되게 관리 |
| 소환 버튼 | 70×66, 초상화 28px, 초상화가 있으면 이름 9px | 전투 중 초상화·비용·쿨타임을 빠르게 구분 |
| 스킬 버튼 | 66×66 원형, 긴 이름은 최소 8px까지 축소 | 긴 빙의 스킬도 핵심 정보 크기를 유지 |
| 전투 상단 | 72px 띠에 자원·미니맵·기지 체력·정보·연계를 배치 | 정보 중요도에 따라 크기와 위치를 재분배 |
| 상태 표현 | 상태 이상은 작은 색 점, 사용 불가는 주로 투명도로 표시 | 형태·아이콘·문구로 원인을 구별 |
| 빌드 | 다수의 66px 이상 노드와 상단 관리 버튼, 252px 상세 패널 | 선행 관계·현재 투자·선택 효과를 쉽게 파악 |
| 지도 | 5×5 사각형 그리드와 우측 상세 패널 | 장별 분위기와 선택·완료·미완료 상태를 구분 |
| 공통 버튼 | 메뉴와 전투 버튼의 형태·상태 처리 방식이 다름 | 역할별 스타일과 입력 피드백 통일 |
| 모바일 설명 | 전투 툴팁은 마우스 hover를 기준으로 열림 | 터치에서도 오조작 없이 설명 확인 |

주요 근거 파일: `src/scenes/layout.ts`, `palette.ts`, `HudButton.ts`, `MenuButton.ts`, `BattleScene.ts`, `BuildScene.ts`, `MapScene.ts`, `Tooltip.ts`, `src/game/buildText.ts`.

## 3. 시각 방향과 공통 규칙

### 기본 테마의 인상

먹빛 밤하늘 위에 따뜻한 등불과 한지 패널을 배치한다. 도깨비·부적·방울·매듭·서낭당을 장식 모티프로 사용한다. 캐릭터의 둥근 SD 외곽선과 어울리는 두께의 프레임을 쓴다. 한지 질감은 넓은 패널에 약하게 사용하고 숫자·작은 글자 뒤는 평탄하게 둔다.

| 역할 | 색상 초안 | 사용 원칙 |
| --- | --- | --- |
| 기본 배경 | 먹남색 `#14172B` | 전장과 메뉴 배경의 바탕 |
| 전투 패널 | 짙은 남색 `#1A1E33` | 전장을 가리지 않는 HUD |
| 밝은 표면 | 한지색 `#F3EAD4` | 메뉴 카드·상세 패널 |
| 주 행동·선택 | 등불 금색 `#E0B52E` | 출전·확정·사용 중 상태 |
| 부적 / 신력 | 금색 / 청색 | 아이콘·명칭을 함께 표시 |
| 위험·피해 | 주홍색 `#D9473B` | 위험 상태, 피해, 실패 안내 |
| 속성 | 기존 오방색 유지 | 태그 의미와 행동 상태 색을 분리 |

- 색상은 출발점이며, 실제 배경 위 대비를 검토한 뒤 확정한다. 색만으로 상태를 전달하지 않는다.
- 제목에는 개성이 있는 한글 서체를 검토하되, 숫자·본문에는 작은 크기에서 선명한 서체를 쓴다. 추가 서체는 사용 조건 확인과 로컬 제공을 전제로 한다.
- 게임 좌표 기준 제목 28~40px, 섹션 18~22px, 본문 14~16px, 조밀한 버튼의 보조 글자 12px 이상을 목표로 한다. 8~9px 축소로 긴 이름을 해결하지 않는다.
- 여백은 4·8·12·16·24px 단위로 정리한다. 기본 프레임은 단순하게 유지하고 장식은 제목·모서리·구분선에 모은다.
- 버튼은 기본·가리킴·키보드 선택·누름·사용 가능·사용 불가·쿨타임을 구분한다. 선택은 테두리와 표식, 불가는 원인 아이콘과 설명을 사용한다.
- 버튼 피드백은 약 80~120ms, 패널 전환은 150~220ms를 초안으로 한다. 연출이 입력이나 전투 진행을 지연시키지 않게 한다.

## 4. 화면별 개편

### 4.1 전투 HUD — 최우선

목표는 전장을 보면서 **지금 소환 가능한 유닛, 사용 가능한 스킬, 위험한 기지 상태**를 즉시 읽는 것이다.

- 상단 왼쪽은 부적·신력, 중앙은 전선·양쪽 기지, 오른쪽은 웨이브·시간·일시정지로 묶는다. 반복되는 명칭과 보조 수치의 시각적 무게를 낮춘다.
- 부적·신력 숫자는 바와 대비되는 고정 영역에 배치한다. 체력 경고는 숫자·아이콘·테두리를 함께 바꾼다. 기지 무적에는 방패와 해제 조건을 표시한다.
- 하단은 이동 / 소환 10칸 / 기운 모으기 / 스킬 3개로 구획한다. 소환 2×5 배치와 1~0 키 대응을 유지한다.
- 소환 카드는 초상화, 짧은 식별 이름, 비용, 키 배지, 남은 쿨타임을 일정한 위치에 둔다. 정식 이름·능력·능력치는 상세 설명에 표시한다.
- 자원 부족·쿨타임·아군 수 제한을 서로 다른 표식으로 보여 준다. 여러 제한이 겹치면 카드에는 우선 사유를, 상세에는 전체 사유를 표시한다.
- 스킬은 전용 아이콘과 Q/W/E 배지를 사용한다. 긴 빙의 스킬 이름은 요약 표기하고 상세에 정식 이름을 표시한다. 빙의 시 현재 형태와 세 스킬이 함께 바뀌었음을 알린다.
- 기운 모으기는 현재 단계, 다음 단계 비용, 현재 가능한 행동을 분리해 표시한다. 클릭·R 키의 기존 동작을 유지한다.
- 영웅 부활은 전용 초상화와 남은 초로 표시한다. 연계는 활성 아이콘과 개수로 요약하고 상세 목록을 따로 펼친다.
- 보스 HUD는 초상화·이름·체력·약점·저항·현재 상태를 정렬한다. 위험 범위 연출은 실제 판정과 일치시키고 기존 패턴 시간을 변경하지 않는다.
- 상태 이상은 작은 색 점을 알아볼 수 있는 아이콘으로 바꾸고 중첩은 숫자로 표시한다. 밀집 전투에서는 우선순위와 표시 개수 제한을 둔다.

배치 초안은 960×540과 기존 하단 패널 높이 150px을 우선 유지한다. 이동 영역 축소, 소환 카드 폭 확대, 기운 모으기 영역 축소로 공간을 재배분한다. 예를 들어 소환 카드 폭 78px·가로 간격 6px의 5열은 414px이다. 최종 좌표는 66×66 이상 터치 영역과 실제 글자 측정을 함께 통과한 뒤 확정한다.

```text
┌ 부적·신력 ──────── 전선·양쪽 기지 ────── 웨이브·시간·정지 ┐
│                   보스 정보 (등장 시)                     │
│                                                          │
│                         전장                             │
│                                                          │
├ 이동 ───── 소환 카드 1 2 3 4 5 ─── 기운 모으기 ── 스킬 ───┤
│  ◀ ▶      소환 카드 6 7 8 9 0      단계·비용      Q W E   │
└──────────────────────────────────────────────────────────┘
```

### 4.2 빌드 — 두 번째 우선순위

- 상단은 보유·사용 가능 신명과 현재 빌드를 먼저 보여 준다. 구매·복사·초기화는 관리 영역으로 묶고 주 행동보다 약하게 표시한다.
- 무당·요괴·연계·살림·소환 순서 탭을 동일한 규격으로 정리한다.
- 무당·연계·살림은 단별 구조를 유지하면서 선행 노드 연결선, 배타 갈래 묶음, 해금 조건을 표시한다.
- 요괴는 10종 초상화와 기본→핵심→각성→빙의 진행을 행 단위로 읽게 한다. 숨은 빙의는 기존 공개 조건 전까지 `???`를 유지한다.
- 우측 상세 패널은 이름 → 현재 단계와 효과 → 다음 단계 변화 → 비용·선행 조건 → 투자·회수 순서로 통일한다.
- 색에 더해 체크·자물쇠·배타 표식으로 투자 완료·가능·잠김·차단을 구별한다.
- 소환 순서는 전투와 같은 초상화·키 배지를 사용한다. 기존 앞뒤 이동 버튼을 기본으로 유지하고 현재 선택을 명확히 한다.
- 노드를 한 화면에 과도하게 압축하지 않는다. 실제 글자 측정 결과 공간이 부족하면 그룹별 탐색을 적용하고 선택 정보는 유지한다.

### 4.3 지도

- 기존 5장×5스테이지 선택 구조와 방향키 이동을 유지한다. 장별 배경 문양·색 띠·연결 경로로 여정의 인상을 더한다.
- 선택됨, 별 0개, 클리어, 별 3개, 보스 스테이지를 테두리·별·배지로 구별한다. 현재 게임에 없는 잠금 규칙은 추가하지 않는다.
- 우측 패널은 스테이지명, 최고 기록·별 조건, 보스 초상화·약점·저항, 현재 빌드, 출전 버튼 순서로 정돈한다.
- 출전을 가장 강하게, 빌드 변경을 보조 행동으로 표시한다. 장식 경로가 버튼 터치 영역을 침범하지 않게 한다.

### 4.4 타이틀

- 밤하늘·등불·마을 실루엣으로 전경·중경·후경을 구성한다. 기존 무당·도깨비 이미지를 장면 안에 자연스럽게 배치한다.
- 게임 제목과 주 버튼을 중심에 두고 설정·조작 안내는 보조 영역으로 이동한다.
- 등불 흔들림과 약한 빛 변화만 사용한다. 시작 버튼을 가리거나 로딩 시간을 늘리는 대형 연출은 피한다.

### 4.5 결과·일시정지·설정·안내

- 결과는 승패, 별과 달성 조건, 시간·기지 체력, 획득 재화, 다음 행동 순서로 보여 준다. 다음 스테이지가 있으면 이를 주 행동으로 강조한다.
- 보상 연출은 계산·저장과 분리한다. 재화 애니메이션이나 반복 클릭으로 보상이 중복 반영되지 않게 한다. 기존 결과 입력 대기 시간을 유지한다.
- 일시정지는 계속하기를 주 행동으로, 지도로 이동을 보조 행동으로 표시하고 기존 기록 안내를 유지한다.
- 설정은 음량과 조작 안내를 구획하고 PC·터치 안내를 각각 읽기 쉽게 제시한다. UI 계획을 위해 새 음향·설정 기능을 확대하지 않는다.
- 로딩, 에셋 누락 대체 표시, 세로 화면 회전 안내에도 같은 색·글자 규칙을 적용한다. 테스트 모드 배지는 항상 구분되게 유지한다.

### 4.6 툴팁과 터치 상세

- PC hover 설명은 유지한다. 터치는 별도 정보 버튼으로 설명 모드를 열고, 이 모드에서 카드를 탭하면 설명을 보여 주며 실제 소환·시전 입력은 전달하지 않는 방식을 우선 검증한다.
- 설명 모드의 시작·종료를 명확히 표시하고 전투 시간은 기존 규칙대로 흐르게 한다. 한 번의 입력이 상세 확인과 전투 행동을 동시에 일으키지 않게 한다.
- 제목 → 역할 → 효과·수치 → 비용·쿨타임 → 현재 불가 사유 순서로 정리한다.
- 화면 밖으로 넘치는 긴 설명은 내부 스크롤 또는 요약·상세 분리로 처리한다. 버튼과 연결되는 표식을 두고, 모달이 열리면 툴팁을 닫는다.

## 5. 기본 UI의 구현 경계

현재 실행 코드는 `default` 스킨의 UI를 사용한다.

1. 기본 전용 색·서체·장식·레이아웃을 `src/ui/default/` 같은 별도 경로로 모은다. 신규 장식 에셋은 `public/assets/ui/default/`에 둔다. 경로명은 구현 시 확정한다.
2. `MenuButton`, `HudButton`, `Tooltip`, `Slider`에는 기본 테마 스타일을 명시적으로 전달할 수 있게 한다. 공통 입력·표시 코드에 기본 세계관 장식을 내장하지 않는다.
3. `palette.ts`의 태그·피해 의미 색상과 기본 메뉴 장식 색상을 구분한다. 공유 상수를 일괄 변경해 다른 용도의 표현이 바뀌는 일을 피한다.
4. 현재 씬의 기본 테마 경로에서 새 프레젠테이션을 연결한다.
5. `src/battle/`의 판정과 데이터 수치를 UI에 맞춰 바꾸지 않는다. 필요한 상태는 기존 모델에서 읽어 표현한다.
6. `BattleScene.ts`의 HUD·보스 표시·결과 표시를 필요에 따라 별도 뷰로 나눈다. UI 개편을 전투 엔진 전체 재작성으로 확대하지 않는다.
7. 캐릭터 원본 아트가 변경되지 않았는지 변경 파일 목록으로 확인한다.

## 7. 완료 기준과 검증

- 전투의 주요 자원·비용·쿨타임·사용 불가 원인을 이름 축소 없이 판독할 수 있다. 긴 이름은 요약과 상세로 해결한다.
- 소환 10칸, 스킬 3개, 이동, 기운 모으기, 일시정지의 조작이 유지된다. 키보드와 터치에서 같은 행동을 수행한다.
- 모든 주요 버튼의 게임 좌표 터치 영역은 66×66 이상이고 서로 겹치지 않는다. 640×360 표시 시 약 44×44 CSS px을 확보하며, 더 작은 화면은 별도 측정한다.
- 960×540·1280×720·640×360 표시와 긴 화면비에서 글자 잘림·모달 넘침·툴팁 가림을 확인한다. 고해상도 기기에서도 논리 좌표와 표시 크기를 혼동하지 않는다.
- 최대 아군·다수 적·비행·성장·보스·빙의·여러 상태가 겹치는 장면에서 캐릭터와 조작부를 식별할 수 있다.
- 잠김·부족·차단·선택 상태는 색을 제거해도 아이콘·문구·형태로 구별된다. 실제 색상 조합의 글자 대비를 확인한다.
- 투자·회수·초기화·복사·구매는 기존 조건과 저장 동작을 유지한다. 숨은 빙의 정보가 선행 공개되지 않는다.
- 회전·창 숨김·일시정지·결과·설정 전환 시 누른 이동 입력과 설명 모드가 남지 않는다. 모달 입력이 뒤 화면으로 전달되지 않는다.
- 장식과 텍스트 객체는 가능하면 재사용한다. 같은 기기·같은 장면에서 개편 전후 프레임 시간과 씬 반복 진입 후 객체 수를 비교한다. 장식 때문에 지속적인 성능 저하나 누수가 생기면 줄인다.
- 이미지 로딩 실패 시 대체 표시를 유지한다.
- 구현 단계에서 기존 `npm test`와 `npm run build`를 통과한다. 레이아웃 변경에는 기존 겹침·최소 크기 검증을 갱신하고, 새 설명 모드의 입력 차단처럼 동작이 추가된 곳에 필요한 검증을 보강한다.

## 9. 적용 결과와 검증 기록

2026-11-05 기본 테마의 전체 화면에 개편을 적용했다.

- `src/ui/default/`: 테마 색·폰트·짧은 표시명, 패널·밤마을 장식, 스크롤 설명 영역을 분리했다. 추가 이미지 다운로드 없이 기존 캐릭터 아트와 코드로 그리는 장식을 사용한다.
- 전투: 80px 소환 카드, 초상화·키 배지·비용·사용 불가 사유, 세로 스킬 카드, 기운 모으기 단계, 기지 외형, 상태 표식, 정돈된 자원 바와 보스 표시를 적용했다.
- 설명 모드: I 또는 설명 버튼으로 열고 카드·숫자·Q/W/E로 대상을 확인한다. 모드 안에서 이동·소환·스킬·기운 모으기는 차단하며 전투 시간은 계속 흐른다. 전체 활성 연계는 설명 모드 첫 화면에서 확인한다.
- 툴팁: 긴 설명을 휠·터치 드래그로 읽는다. 설명 영역은 전투 하단 버튼 위에 머물고 상태 줄은 고정한다. 텍스트 crop을 사용해 Canvas와 WebGL에서 같은 영역을 표시한다.
- 빌드: 선행 연결선·배타 갈래 테두리·상태 표식·요괴 초상화, 현재와 다음 레벨·비용·선행 조건, 고정된 스크롤 상세 영역을 적용했다. 기존 숨은 빙의 공개 조건을 유지한다.
- 타이틀·지도: 달·마을·등불 배경과 한지·금색 버튼을 적용하고, 장별 경로와 보스 초상화·출전 정보를 정리했다.
- 결과·일시정지·설정·로딩·회전 안내: 공통 패널 스타일을 적용했다. 결과에서는 다음 스테이지를 먼저 배치하고, 설정은 소리·조작 안내 탭으로 나눴다.
- 멀티터치: 버튼을 누른 포인터를 추적해 소환한 손가락을 떼어도 이동을 누른 다른 손가락이 해제되지 않게 했다.

검증 결과:

- `npm test`: 35개 파일, 634개 테스트 통과. 18개 전투 버튼의 최소 크기·영역·겹침 검증 포함.

- 빌드 투자, 확인창의 뒤쪽 입력 차단, 소환 순서 변경, 새로고침 후 저장 유지, 결과 보상 기록 안정을 확인했다.

## 10. 사용 피드백 반영: 초상화·관문·게이지

- 생산 버튼의 초상화를 34px에서 64px로 확대했다. 이름과 상시 상태 문구는 상세 설명으로 옮기고, 비용은 18px 배지로 표시한다. 쿨타임은 초상화 위의 원형 가림과 큰 숫자로, 자원 부족·정원 제한은 작은 불가 표식과 상세 설명으로 표시한다.
- 지도는 25칸 표 대신 장 탭 5개와 현재 장의 관문 5개를 보여 준다. 관문을 선택하면 큰 미리보기에서 이름·최고 별·목표 시간·보스 상성을 확인한 뒤 출전한다. 빌드에서 돌아와도 선택한 관문을 유지한다.
- 지도에 처음 들어갈 때 첫 미클리어 관문을 추천한다. 모두 클리어한 기록은 별이 부족한 첫 관문, 별을 모두 모은 기록은 마지막 관문을 선택한다. 기존 자유로운 스테이지 도전 범위는 유지한다.
- 자원·기지 게이지는 의미별 아이콘·큰 숫자·분리된 둥근 채움 바를 사용한다. 수치 변화는 표시만 부드럽게 연결하며 실제 자원·체력 계산은 바꾸지 않는다. 전장 체력바와 보스바에도 둥근 끝과 밝기 표현을 적용했다.
- 관문 추천과 새로운 장·관문 터치 영역 검증을 포함해 637개 테스트 및 빌드가 통과했다. 960×540·640×360의 출전 흐름, 초상화·비용·쿨타임·상세 설명, 게이지 표시, 멀티터치를 로컬 Chrome에서 확인했다. 캡처와 검증 로그는 `output/ui-refinement/`에 둔다.
