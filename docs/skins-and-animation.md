# 스킨 등록·선택 및 캐릭터 애니메이션 설계

작성일: 2026-11-04 · 상태: 구현 전 설계

종류별 실제 이미지 제작 설명은 [캐릭터 이미지 제작 가이드](art/default/README.md)를 참고한다. 영웅·아군·적·보스 26종의 개별 외형, PNG 파일별 포즈, 추가 스킨 콘셉트를 정리했다.

## 1. 목표와 우선순위

지금은 완성된 스킨 이미지가 없다. 먼저 **캐릭터 종류마다 여러 스킨을 등록하고, 목록에서 고른 스킨을 저장하고 적용하는 구조**를 만든다. 실제 그림과 동작 프레임은 나중에 준비되는 순서대로 추가한다.

스킨 하나는 단순한 색상 값이 아니라 한 캐릭터의 외형 묶음이다. 대기·이동·공격·피격·퇴장 이미지와 표시 크기, 기준점, 기본 방향을 함께 정의한다. 예를 들어 방망이 도깨비에 기본 스킨과 축제 의상 스킨을 각각 등록하고, 각 스킨 안에 여러 장의 걷기 이미지를 넣는다.

우선순위는 다음과 같다.

1. **1차: 이미지 없이도 동작하는 스킨 등록·선택·저장·대체 표시 구조.**
2. **2차: 대표 아군·적·영웅의 이미지 표시, 좌우 반전, 걷기, 피격 표현.**
3. **3차: 종류별 공격·소환·퇴장 프레임과 보스 고유 동작 확장.**

이 문서는 구현 지침이다. 현재 요청의 산출물은 문서이며, 아래 기능이나 이미지 제작이 완료되었다는 뜻은 아니다. 프레임 수와 연출 시간은 초기 제작 권장값으로 두고 실제 플레이를 보며 조정한다.

## 2. 현재 코드와 연결 지점

| 현재 파일 | 확인된 구조 | 향후 연결할 내용 |
| --- | --- | --- |
| `src/data/allies.ts`, `enemies.ts`, `bosses.ts` | 종류별 `id`와 전투 수치 | 기존 ID를 스킨 대상 식별에 사용 |
| `src/data/hero.ts` | 영웅 수치 정의, 별도 `id` 없음 | 외형 계층에서 `hero:kkomaMudang` 같은 고정 키 부여 |
| `src/battle/entities.ts` | `Fighter.defId`, 진영, 크기 배율, 고정 전진 방향 | 외형과 전투 데이터를 분리한 채 조회 |
| `src/battle/hero.ts` | 영웅의 마지막 이동 방향인 `facing` 보유 | 좌우 반전의 기준으로 사용 |
| `src/scenes/BattleScene.ts` | 매 프레임 Graphics를 비우고 도형으로 캐릭터 표시 | 캐릭터 본체를 지속적으로 유지하는 Sprite/View로 교체 |
| `src/scenes/BootScene.ts` | 에셋 로딩 없이 다음 화면으로 이동 | 등록된 에셋 로딩 및 실패 처리 추가 |
| `src/battle/damageEvents.ts` | 피해 숫자용 이벤트, 화상 피해는 일정 간격으로 합산 | 직접 타격 반응과 숫자 표시를 구별 |
| `src/game/save.ts`, `session.ts` | 전역 저장과 localStorage 처리 | 선택한 스킨 저장 및 이전 저장 호환 |

전투 판정은 계속 `src/battle`이 담당하고, 텍스처·프레임·깜박임은 화면 계층이 담당한다. 스킨을 바꿔도 체력, 공격력, 공격 간격, 이동 속도, 사거리, 충돌 반경은 바뀌지 않는다.

## 3. 종류와 스킨을 구분하는 규칙

- **대상 키(subjectKey)**: `ally:clubGoblin`, `enemy:eggGhost`, `boss:giantWonGwi`, `hero:kkomaMudang`처럼 분류와 종류 ID를 합친다.
- **스킨 ID(skinId)**: 해당 대상 안에서 `default`, `festival`처럼 구분한다. 대상 키와 스킨 ID의 조합은 고유해야 한다.
- **개체(instance)**: 전투에서 같은 도깨비를 다섯 마리 소환하면 외형 View는 다섯 개지만 스킨 정의와 텍스처는 공유한다.
- 모든 대상에는 `default` 정의가 있어야 한다. 이미지가 없어도 도형 표시로 기본 스킨을 제공한다.
- 화면에 표시하는 이름과 파일 경로를 식별자로 쓰지 않는다. 표시 이름을 바꿔도 저장된 선택이 유지되어야 한다.
- 정예·각성·성장·보스 패턴은 전투 상태다. 스킨 선택과 분리하고 크기 배율이나 별도 효과로 표현한다.

아군 10종, 일반 적 10종, 보스 5종, 영웅 1종을 등록 대상으로 삼는다. 기지·배경·투사체 스킨은 이후 확장 대상으로 둔다. 서로 다른 종류끼리 스킨을 잘못 장착할 수 없어야 한다.

## 4. 데이터 중심 등록 구조

권장 파일 배치는 다음과 같다. 아래 경로와 타입은 새로 추가할 설계 예시다.

```text
src/data/skins.ts                 대상별 스킨 목록과 기본 스킨
src/data/skinTypes.ts             스킨·클립·에셋 형식
src/game/skins.ts                 목록 조회, 선택, 선택값 검증
src/render/CharacterView.ts       도형/Sprite 표시와 정리
src/render/CharacterAnimator.ts   동작 상태, 방향, 연출 시간
src/scenes/SkinScene.ts           선택 화면과 미리보기
public/assets/characters/         추후 추가할 이미지 파일
```

```ts
type AnimationState = 'idle' | 'walk' | 'attack' | 'hit' | 'spawn' | 'death';

interface SkinDef {
  subjectKey: string;
  skinId: string;
  name: string;
  renderer: 'placeholder' | 'sprite';
  // assetKey는 별도 에셋 목록에 등록된 이미지/시트/아틀라스를 참조한다.
  assetKey?: string;
  previewFrame?: string | number;
  facing: 'right' | 'left';
  origin: { x: number; y: number };
  displayHeight?: number;
  clips: Partial<Record<AnimationState, {
    frames: Array<string | number>;
    fps: number;
    loop: boolean;
  }>>;
}

interface SkinSelectionData {
  selectedBySubject: Record<string, string>;
}
```

별도 에셋 목록에는 `assetKey`, 형식(`image` / `spritesheet` / `atlas`), 상대 경로를 등록한다. 시트에는 프레임 폭·높이·여백·간격을, 아틀라스에는 이미지와 JSON 경로를 함께 기록한다. 단일 이미지는 정지 프레임 하나로 취급한다. 스킨의 프레임 참조는 해당 에셋 안에서 해석한다.

최초에는 `placeholder`만 구현해도 된다. 이후 Sprite를 추가해도 선택·저장 형식을 그대로 사용한다. 종이 인형 렌더러가 필요해지면 동일한 선택 구조에 별도 렌더러를 추가한다.

등록 시 중복 ID, 없는 대상 키, 잘못된 에셋 참조, 빈 프레임 목록, 0 이하 FPS를 검증한다. 텍스처·애니메이션 키에는 대상 키와 스킨 ID를 포함해 서로 덮어쓰지 않게 한다.

추가 스킨 하나를 등록할 때 전투 로직이나 선택 화면의 조건문을 수정하지 않고, 정의와 에셋만 추가하면 목록에 나타나야 한다. 1차의 “등록”은 개발자가 데이터에 추가하는 방식이다. 게임 안에서 파일을 업로드하는 관리자 기능은 이번 범위에 포함하지 않는다.

## 5. 스킨 선택과 저장

### 선택 화면

- 타이틀 또는 지도에서 `외형 / 스킨` 화면으로 들어간다.
- 영웅 / 아군 / 적 / 보스 분류에서 종류를 고른 후, 그 종류에 등록된 스킨 카드를 나열한다.
- 카드에는 이름, 미리보기, 현재 적용 표시를 보여 준다. 아직 이미지가 없는 항목에는 `이미지 준비 중`과 대체 도형을 표시한다.
- 카드를 누르면 미리보기만 바뀌고, `적용`을 누르면 저장한다. 뒤로 가면 미적용 선택을 버린다.
- 미리보기에는 대기 / 이동 / 공격 / 피격과 좌우 방향 전환을 확인할 수 있는 조작을 둔다. 없는 동작은 대체 표시를 사용한다.
- 첫 버전은 등록된 스킨을 모두 선택할 수 있게 한다. 구매·희귀도·해금 재화는 추가하지 않는다.

아군과 영웅뿐 아니라 적·보스도 종류별로 선택할 수 있게 한다. 선택하지 않은 적과 보스는 기본 스킨을 사용한다. 추후 스테이지 전용 외형이 필요하면 별도의 지정 규칙을 추가하되, 첫 버전은 저장된 종류별 선택만 사용한다.

선택은 계정 진행·빌드 슬롯과 독립적인 전역 설정으로 저장한다. 전투 시작 때 선택값을 복사해 그 전투 전체에 적용한다. 같은 종류로 나중에 소환되는 개체도 같은 스킨을 쓴다. 전투 중 실시간 스킨 변경은 후순위다.

### 저장 호환과 대체 표시

`SaveData`에 `skins: SkinSelectionData`를 추가하고 `GameSave`, `snapshot()`, `persist()`, `session.ts`에 연결한다.

- 과거 저장에 `skins`가 없으면 모든 종류가 기본 스킨을 사용한다.
- 존재하지 않는 대상·스킨 ID나 다른 종류의 스킨 선택은 제거하고 해당 종류의 기본값을 쓴다.
- 기본 스킨의 이미지도 없으면 현재 도형을 그린다. 빈 캐릭터나 로딩 실패 화면을 만들지 않는다.
- 저장하는 것은 선택 ID뿐이다. 이미지 데이터·텍스처·애니메이션 진행률은 저장하지 않는다.
- localStorage 접근이 실패해도 현재 실행에서는 선택을 유지한다.

현재 `sanitizeSave()`는 저장 버전이 다르면 전체 기본값을 반환한다. **단순 필드 추가를 위해 버전만 올리면 기존 진행도가 초기화될 수 있다.** 현재 버전을 유지하며 누락 필드를 보정하거나, 버전을 올릴 경우 기존 별·재화·빌드·소환 순서·설정을 보존하는 마이그레이션을 먼저 구현한다.

이미지 로딩 실패 시에는 선택 ID를 지우지 않고 임시 도형으로 표시한다. 파일이 복구된 다음 실행에서 원래 스킨을 다시 사용할 수 있게 한다.

## 6. 동작별 이미지 구성

최종 아트 납품은 모든 테마·추가 스킨에 공통 본체 19컷(대기 2·이동 4·공격 4·피격 2·등장 3·퇴장 4)을 적용한다. 개별 MD의 고유 동작·효과는 별도다. 파일명은 `idle_00~01`, `walk_00~03`, `attack_00~03`, `hit_00~01`, `spawn_00~02`, `death_00~03`이며 각각 PNG다. 비행·롤러도 파일명은 `walk`이고 실제 자세만 다르게 한다.

이 수량은 최종 스킨 제작 계약이다. 초기 도형·이미지 누락 대체 표시·단계적 로딩은 계속 허용하지만 기준 원화 1장이나 리깅 자료만으로 최종 납품을 완료하지 않는다. 같은 스킨의 프레임은 캔버스·방향·피벗을 통일하고 공격 타격·발사는 실제 전투 이벤트에 맞춘다.


각 종류는 자신의 체형과 이동 방식에 맞는 프레임을 가진다. 방망이 도깨비와 까치 떼가 같은 걷기 이미지를 공유하는 식으로 만들지 않는다. 다만 같은 종류의 의상 스킨끼리는 프레임 이름과 상태 구성을 맞추면 관리하기 쉽다.

| 동작 | 초기 권장 프레임 | 재생 방식 | 표현 목표 |
| --- | --- | --- | --- |
| 대기 `idle` | 1~2장 | 반복, 약 2~4 FPS | 숨쉬기, 작은 흔들림 |
| 이동 `walk` | 4~6장 | 반복, 약 6~10 FPS | 발 번갈아 딛기, 몸과 무기의 리듬 |
| 공격 `attack` | 3~5장 | 1회 | 준비 → 타격 자세 → 회수 |
| 피격 `hit` | 1~2장 | 약 80~140ms | 움찔, 표정 변화, 짧은 색 강조 |
| 소환 `spawn` | 2~4장, 선택 | 1회 | 부적 효과와 등장 |
| 퇴장 `death` | 3~5장, 선택 | 1회 | 겁먹은 표정, 연기처럼 사라짐 |

첫 이미지 세트는 `idle 1장 + walk 4장`부터 준비해도 된다. 공격·피격·퇴장은 한 장을 짧게 회전·변형·점멸·페이드하는 대체 연출을 제공한다. 필요한 모든 그림이 완성될 때까지 구현을 미루지 않는다.

그림 제작 시 같은 스킨의 모든 프레임은 투명 배경, 동일한 캔버스 크기, 동일한 발바닥 기준점, 일관된 체형·색·무기 위치를 유지한다. 매 프레임 자동 크롭하면 기준점 보정 없이는 캐릭터가 튀므로, 동일 캔버스를 쓰거나 아틀라스의 잘림·원본 크기 메타데이터를 반영한다.

예시 에셋 구성:

```text
public/assets/characters/ally/clubGoblin/default/
  atlas.png
  atlas.json        # idle_0, walk_0~3, attack_0~2, hit_0 등
  preview.png      # 선택 사항
```

낱장 PNG로 제작해도 되며, 로딩 전에 공통 에셋 목록에 등록한다. 구현 초기부터 아틀라스 제작 도구를 필수로 요구하지 않는다. `public` 아래 파일의 URL에는 `public/`을 넣지 않고 Vite의 배포 기준 경로를 반영한다. 현재 `base: './'` 설정과 하위 경로 배포에서도 에셋이 열려야 한다.

## 7. 좌우 이동과 자연스러운 반전

이 게임의 이동은 가로축 기준이다. 이 문서의 “앞뒤”는 좌우 진행·방향 전환을 뜻하며, 위아래 이동이나 캐릭터의 등 전용 그림까지 요구하지 않는다.

1. 원본 이미지는 원칙적으로 오른쪽을 바라보게 만든다. 왼쪽을 볼 때 본체 Sprite 또는 외형 루트만 좌우 반전한다. 기본 방향이 다른 에셋은 `facing` 값으로 보정한다.
2. 영웅은 기존 `Hero.facing`을 기준으로 하고, 멈췄을 때 마지막 방향을 유지한다. 걷기 재생 여부는 입력만이 아니라 실제 이동 상태로 결정한다.
3. 일반 아군·적은 평상시 `Fighter.direction`으로 전진한다. 공격할 때는 실제 대상의 위치를 향한다. 공격 대상이 사라지면 마지막 방향을 유지하다가 전진할 때 진행 방향으로 맞춘다.
4. 넉백으로 밀리는 것은 걷기와 구분한다. 위치 변화만 보고 뒤를 돌아 걷게 하지 않고 기존 시선을 유지하며 피격·밀림을 표현한다.
5. 발바닥이 닿는 중심을 기준점으로 삼고, 반전할 때 월드 좌표나 지면 높이가 바뀌지 않게 한다. 좌우 반전 때문에 크기 배율의 부호를 계속 곱하지 않는다.
6. 체력바, 이름, 피해 숫자, 상태 아이콘은 본체의 반전 대상에서 제외한다. 무기 부착점·공격 효과의 상대 좌표는 방향에 맞춰 반전한다.
7. 같은 걷기 상태를 매 프레임 처음부터 재생하지 않는다. 방향이 바뀌어도 같은 클립이면 진행률을 유지해 발동작이 끊기지 않게 한다.

이동 속도에 따라 걷기 재생 속도를 제한된 범위에서 조절해 발 미끄러짐을 줄인다. 감속·정지·기절 중에는 달리듯 제자리걸음하지 않게 한다. 빠른 이동의 프레임 속도에는 상한을 둔다.

비행 유닛은 걷기 대신 날갯짓이나 부유 동작을 사용하며, 현재 `liftOf()`의 고도와 지면 그림자를 유지한다. 그슨대의 성장, 정예 배율, 보스의 착지·비행 전환도 기존 전투 상태를 읽어 표시한다. 스킨마다 임의의 충돌 크기를 만들지 않는다.

무기·문양의 좌우가 중요한 스킨은 나중에 좌·우 전용 클립을 등록할 수 있게 확장한다. 별도 클립이 없으면 공통 클립과 반전을 사용한다. 실제 뒷걸음질 이동을 추가할 때는 시선과 이동 방향을 분리하고 후진 클립을 별도로 정의한다.

## 8. 동작 상태와 피격 처리

### 상태 전환

기본 동작은 `spawn → idle / walk ↔ attack → death`로 관리한다. 기절·붙잡기 중에는 기본 이동·공격 동작을 멈추고 상태 표시를 유지한다. 사망은 다른 모든 연출보다 우선하며, 같은 동작으로 유지되는 동안에는 재시작하지 않는다.

공격은 매번 새 공격이 발생했을 때 한 번 시작하고, 종료 후 실제 이동 여부에 따라 대기나 걷기로 돌아간다. 쿨타임이 남아 있다는 이유만으로 공격 자세를 계속 재생하지 않는다. 공속이 빨라지면 다음 공격까지 회수 동작이 끝나도록 길이를 조절하거나 이전 동작을 정리한다.

현재 전투는 공격 판정과 투사체 발사가 코드에서 즉시 처리된다. 첫 도입에서는 이 시점을 유지하고 타격·발사 자세를 그 시점에 맞춘다. 준비 동작을 넣는다는 이유로 피해나 발사 시점을 임의로 늦추지 않는다. 준비 시간과 실제 판정을 연결하는 변경은 별도 전투 설계로 다룬다.

### 피격은 별도 반응으로 겹친다

- 실제 직접 피해를 받으면 약 80~140ms 동안 전용 피격 프레임 또는 색 강조와 짧은 외형 흔들림을 적용한다.
- 공격 중에는 기본적으로 색 강조와 작은 흔들림만 겹쳐 공격 동작이 매번 끊기지 않게 한다. 피격만으로 공격 취소·경직·무적 시간을 만들지 않는다.
- 외형 흔들림은 View의 로컬 좌표만 움직인다. 전투상의 `x`, 충돌, 타격 거리에는 영향을 주지 않는다.
- 연속 타격 시 반응 시간을 제한하고 흔들림을 누적하지 않는다. 공격이 몰려도 캐릭터가 계속 사라져 보이거나 위치가 밀려나지 않게 한다.
- 면역·피해 0은 일반 피격과 구분한다. 화상은 현재 합산 피해 숫자를 직접 타격으로 취급하지 않고 불꽃·색 변화 등 지속 효과로 보여 준다.
- 상태 효과 색과 스킨 원래 색은 효과 종료 후 복원한다. 같은 틴트 값을 덮어쓰는 방식으로 버프·피격 표시가 영구히 남지 않게 한다.

### 전투 이벤트 연결

공격 시작·발사·직접 피격·사망처럼 순간적인 사실은 전투 측에서 이벤트로 내보내고, 이동·기절·비행 같은 지속 상태는 읽어서 표시한다. 순간적인 사건을 쿨타임 변화나 HP 비교만으로 추측하지 않는다.

기존 `drainDamageEvents()`는 `BattleScene.updateFloaters()`가 소비한다. 새 애니메이터가 다시 drain하면 이벤트를 놓친다. 화면에서 한 번 받아 여러 표현에 전달하거나 별도 시각 이벤트 스트림을 둔다. 기존 숫자용 화상 합산 이벤트만으로 모든 피격 타이밍을 구현하지 않는다.

여러 적을 동시에 맞히는 공격은 공격자 동작을 1회, 피격자는 대상별로 처리한다. 화상·직접 피해·실제 사망을 구분하고, 한 개체에 사망 이벤트를 중복 발생시키지 않는다. 전투 로직에는 Phaser 의존성을 추가하지 않는다.

## 9. 이미지가 부족할 때의 동작

| 부족하거나 실패한 항목 | 대체 표시 |
| --- | --- |
| 스킨 정의가 없음 / 잘못된 선택 | 그 종류의 `default` |
| 텍스처 로딩 실패 | 현재 진영·종류를 식별할 수 있는 기본 도형 |
| 대기 프레임 없음 | 사용 가능한 대표 프레임, 그것도 없으면 도형 |
| 걷기 프레임 없음 | 대표 이미지와 작은 상하 움직임·기울기 |
| 공격 프레임 없음 | 대표 이미지의 짧은 회전·앞쪽 외형 이동 |
| 피격 프레임 없음 | 짧은 색 강조·흔들림 |
| 소환·퇴장 프레임 없음 | 짧은 등장·페이드 또는 연기 효과 |
| 미리보기 이미지 없음 | 대표 프레임 또는 대체 도형 |

대체 연출은 사망·일시정지·화면 종료 시 정리한다. 선택 화면에도 실제 사용할 대체 모습을 보여 준다. 이미지가 없는 스킨을 선택할 수는 있지만 완성된 그림이 있는 것처럼 표시하지 않는다.

## 10. 렌더링과 수명 관리

- `Map<Body, CharacterView>`처럼 전투 개체와 View를 연결한다. 현재 `Body`에는 고유 ID가 없으므로 `defId`만으로 View를 관리하면 같은 종류 여러 마리가 하나로 합쳐진다.
- 개체 생성 때 View를 만들고 이후 위치·상태만 갱신한다. 매 프레임 Sprite·애니메이션·텍스처를 새로 생성하지 않는다.
- 캐릭터 본체, 그림자, 오라, 투사체, 체력바, 상태 표시의 깊이를 명시한다. Graphics 하나와 Sprite를 섞을 때 체력바가 본체 뒤로 가려지지 않게 레이어를 분리한다.
- 아트의 기준 표시 높이는 종류별 기존 크기에 맞추고, 정예·성장 배율은 별도로 곱한다. 프레임이 바뀔 때마다 보이는 픽셀 경계로 다시 크기를 계산하지 않는다.
- 현재 전투 step은 죽은 개체를 배열에서 제거한다. 마지막 좌표·방향·스킨·배율을 받아 짧은 퇴장 View를 유지한 뒤 해제한다. 죽은 개체를 전투 배열에 다시 넣지 않는다.
- 영웅은 부활 시 이전 피격·퇴장 상태를 초기화하고 정상 View로 돌아간다.
- 일시정지 중에는 애니메이션·피격 타이머·퇴장 효과도 멈춘다. 재개 시 멈춘 시간만큼 한꺼번에 진행하지 않는다.
- 전투 종료·재시작·장면 이탈 시 View, 리스너, 타이머, Tween을 정리한다. 공유 텍스처는 사용하는 장면이 있을 때 해제하지 않는다.
- 첫 버전은 작은 공통 에셋 묶음을 미리 로딩해도 된다. 스킨이 늘어나면 선택된 스킨과 해당 전투에서 필요한 종류만 로딩한다. 실패한 파일을 매 프레임 재요청하지 않는다.

## 11. 구현 단계와 완료 기준

### A. 구조 먼저 — 이번에 우선 개발할 범위

- [ ] 모든 대상에 도형 기반 기본 스킨을 등록한다.
- [ ] 같은 종류에 2개 이상의 임시 스킨을 등록해 목록이 데이터대로 늘어나는지 확인한다. 이름·대체 색상 등으로 구분하고 `이미지 준비 중`을 표시한다.
- [ ] 종류별 선택·미리보기·적용·저장 화면을 만든다.
- [ ] 선택한 스킨을 전투 시작 시 반영한다. 해당 종류의 모든 소환 개체에 일관되게 적용한다.
- [ ] 이미지 없는 스킨과 잘못된 저장값이 기본 표시로 복구된다.
- [ ] 이전 저장의 별·재화·빌드·소환 순서·설정이 보존된다.
- [ ] Sprite와 동작 클립을 나중에 추가할 수 있도록 표시 계층을 분리한다.

**완료 기준:** 실제 그림이 하나도 없어도 여러 스킨의 등록·선택·저장·전투 적용을 확인할 수 있다. 전체 애니메이션 구현이나 이미지 제작은 A 단계 완료 조건으로 요구하지 않는다.

### B. 대표 종류로 이미지와 동작 검증

- [ ] 영웅, 지상 아군 1종, 지상 적 1종에 대표 이미지와 걷기 프레임을 연결한다.
- [ ] 영웅의 좌우 이동·정지, 적의 왼쪽 전진, 공격 대상 방향을 확인한다.
- [ ] 좌우 반전 때 발바닥과 그림자가 튀지 않고 체력바·글자가 뒤집히지 않는다.
- [ ] 공격·피격·사망 이벤트를 연결하고, 프레임이 없는 동작의 대체 효과를 확인한다.
- [ ] 넉백·기절·감속과 일반 이동이 시각적으로 구별된다.
- [ ] 비행 유닛 1종과 성장·착지하는 종류로 고도·크기 변화를 확인한다.

### C. 종류별 에셋 확대

- [ ] 아군 10종, 적 10종, 보스 5종, 영웅 1종의 기본 외형을 순차 적용한다.
- [ ] 각 종류에 맞는 공격·비행·피격·소환·퇴장 클립을 추가한다.
- [ ] 같은 종류의 추가 의상 스킨도 정의·파일 등록만으로 추가된다.
- [ ] 다수 소환·광역 타격·연속 피격·장면 재시작에서 프레임 저하나 View 누수가 없는지 확인한다.
- [ ] 에셋 출처·라이선스를 기록한다.

구현 시에는 스킨 조회·선택 검증·저장 호환·순간 이벤트 중복 방지처럼 결과가 중요한 로직을 테스트한다. 화면은 미리보기와 실제 전투에서 방향·발 위치·피격·일시정지·부활을 확인하고, 타입 검사·기존 테스트·프로덕션 빌드도 통과시킨다.

## 12. 기존 아트 설계와의 관계

기존 `docs/design.md` 8장의 한국 민담 분위기, 오방색, 투명 PNG, 오른쪽 원본 방향, 에셋 출처 기록 원칙은 유지한다. 기존에 정한 종이 인형 방식에 더해 **종류별 여러 이미지 프레임을 사용하는 방식도 지원하는 방향으로 확장**한다.

첫 이미지 구현은 통짜 이미지·프레임 애니메이션부터 적용할 수 있다. 부위별 원화가 준비된 종류는 이후 종이 인형 방식을 선택할 수 있지만, 첫 단계에서 모든 렌더러를 구현하지 않는다. 스킨 선택·저장 구조는 제작 방식에 공통으로 사용한다.

이미지 제작·수급은 별도 작업이다. 준비 순서는 구조 A → 대표 에셋 B → 전체 종류 C로 하고, 초기부터 26종의 모든 스킨과 모든 프레임을 한꺼번에 요구하지 않는다.
