# 꼬마 무당 대소동 (가제) 작업 목록

횡스크롤 라인 디펜스 웹 게임. 설계 `docs/design.md`, 수치 `docs/numbers.md`, 변경 이력 `CHANGELOG.md`.
기술 스택: Phaser 4 + TypeScript + Vite, 테스트 vitest. 5737 포트는 다른 프로젝트가 쓰므로 사용하지 않는다.

## 진행 원칙
- 사용자가 시작하라고 한 항목만 진행하고, 끝나면 멈추고 보고한다.
- 코드 작업은 dev-cycle(code-writer → code-verifier → feedback-synthesizer)로 진행한다. 사용자가 사이클 없이 하라고 하거나 "개발만" 하라고 하면 따른다.
- 문서에 없는 값은 구현 전에 정해서 지시하고, 정한 내용은 아래 "코드가 정한 해석"에 남긴다.
- 커밋은 요청이 있을 때 commit-release 규칙(버전·CHANGELOG 확인 후 커밋)으로 한다. push는 요청이 있을 때만 한다.
- push 후 배포 확인(Actions·사이트)은 요청이 없으면 하지 않는다.

## 코드가 정한 해석 (문서에 없던 값, 설계 확인 시 참고)

### 전투 기본 (1·2단계)
- 유닛끼리는 서로 막지 않고 겹쳐 지나감
- 사거리 = 중심 거리 − 대상 반지름, 가장 가까운 대상 선택. 영웅도 원귀의 성을 때릴 수 있고 기지 타격에도 신력 +2
- 이전 장의 적은 다음 장 1번째 스테이지부터 등장
- 소환 위치 아군 x=130, 적 성 앞 40px, 투사체 속도 420 (`data/combat.ts`)
- 부활 시간은 사망 시점의 위협 단계로 고정, 부활 위치 x=130
- 소환 실패 시 쿨타임 소모 없음

### 상성·상태 효과 (3단계 A)
- 화상: 공격력 버프·공격 유형 배율·최소 피해 1 제외, 불 태그 배율과 받는 피해 증감만 적용. 재적용 시 초당 피해는 큰 쪽 유지
- 방어 파괴의 받는 피해 증가는 감소 상한 70%와 별개: 1 + 증가 − min(감소, 0.7)
- 오라는 매 틱 다시 적용, 같은 종류도 합산, 영웅도 아군 오라를 받음. 투사체 공격력 버프는 발사 시점 값
- 마법 범위 `|dx| − 대상 반지름 ≤ 반경`, 기지는 주 대상일 때만 맞음. 기절 중에도 공격 쿨타임은 줄어듦

### 고유 능력·연계 (3단계 B)
- 해태: 소환 직후 사용 가능, 이후 8초 쿨타임. "가장 앞" = 사거리 안 x가 가장 큰 적, 비행 제외, 기절 중 미사용
- 영등 빗나감: 도착 시점 1회 판정, 영등·대상이 해제 중이면 무효, 영웅 포함·서낭당 제외, 여러 영등은 최고 확률 하나만
- 오라 소유자(삼족오·영등·해태 ③·수호 연계의 해태 등, 영웅 소유 오라 포함)가 버프 해제 중이면 그 동안 오라를 내보내지 않음. 해제가 끝나면 다시 내보냄. 차사왕 오라 무효는 별개로 그대로
- 저승사자: 대상이 없어도 6초마다 발동, 기절 중엔 대기
- 그슨대: 몸집 ×1.08/단계(반지름도), 성장은 기절과 무관
- 신수의 축복: 최대 체력만 늘리고 현재 체력은 올리지 않음. 백귀야행·수호의 맹세 Ⅱ는 영웅 포함
- 불바람 확산 값 = 맞은 적의 가장 센 화상(불씨 Ⅰ 반영), 강철이에게는 확산 안 됨
- 공격자 쪽 배율(외다리, 까치, 도깨비불, 두억시니 서낭당 ×2)은 곱셈, `strike`에서 한곳에 적용

### 영웅 스킬 (4단계)
- 스킬 피해는 고정 수치: 공격력 버프·연계 미적용, `calcDamage` 직접 호출

- facing = 마지막 이동 방향, 시작·부활 시 오른쪽, 기절 중 고정. 태그 면역으로 피해 0이면 넉백·기절 미적용

- 변신 기본 공격: 공격력은 (25 × 방울 단련) × 1.5(`POSSESSION_TUNING.basicAttackMultiplier`), 간격은 영웅 값(유닛 ① 공격력 +25%는 영웅에 미적용). 유닛 화상 값은 ×1.5 하지 않음. 무당 각성 충격파는 이 기본 공격력 기준이라 함께 오름(빙의 중 25×1.5×1.5=56.25). 사거리 근접 50 / 원거리·마법은 유닛 사거리, 화상 초당·마법 범위는 ②③ 반영 값, 방어 파괴 최대 중첩은 ② 반영, 까치 비행 ×2는 기본 능력 값만(③ ×3·0.3초 경직은 안 붙음)
- 영웅 태그가 늘어도 연계는 영웅 공격에 적용되지 않는다(source 'hero'). 무당 각성 충격파도 영웅+유닛 태그를 쓰고 빙의 중에도 유지. 신력 +2는 그대로
- 빙의 스킬: 슬롯 id는 기존 fanWind(Q)·blessing(W)·bladeDance(E) 재사용. 신내림·스킬 갈래는 빙의 스킬에 미적용, 쿨타임은 빙의 공통값 고정(Q 2.4 / W 4.8 / E 16초, 신력 12/16/32). 스킬 표의 피해·화상·충돌 피해는 기준값이고 실행 시점에 ×1.5(`damageMultiplier`·`burnMultiplier`)를 곱함, 툴팁은 곱한 값을 보여 줌. 피해는 `dealFixedDamage`(연계·공격력 버프 없음). 화상은 불 태그 스킬에만, 태그 면역(강철이 불)이면 피해 0·상태 효과 없음
- "가장 가까운 적" 계열은 영웅에서 400(`NEAREST_REACH`) 안, 방향 무관, 근접 유형 스킬은 비행 적 제외(원거리·마법은 비행 포함). 돌진은 출발~도착점 사이 땅 위 적, 영웅이 즉시 이동. 연속 타격은 첫 타 즉시 + 간격마다 영웅 현재 위치 기준으로 다시 판정(영웅 사망 시 중단)
- 소환형 스킬은 상한이 차도 시전은 성공(소환 0마리), 소환 위치·업그레이드 반영은 일반 소환과 같음. 도깨비 잔치는 거리 제한 없이 도깨비 태그 아군 전체 + 영웅
- 유닛 6~10 스킬 15개 추가로 10종 모두 빙의 스킬을 쓴다("준비 중" 표시·기본 무당 스킬 대체 없음). 새 기본 동작은 `flyingMultiplier`(비행 적 피해 배율)·`flyingOnly`(비행 적만 대상)·buff의 `heroEffect`·aura의 `missChance`
- 쇠 갑옷: 영웅은 `heroEffect`(−50%)만 받고 반경 150 다른 아군은 −25%, 영웅이 두 수치를 함께 받지 않는다. 해제 중인 대상에는 걸리지 않음
- 탐식 회복: 이 스킬 피해로 죽은 적 수 × 영웅 최대 체력 10%, 회복 차단 중이면 0 (`Hero.heal`)
- 순풍 빗나감: 도착 시점에 영웅 중심 반경 250(중심 거리) 안 아군·영웅을 노리는 적 투사체에 최고 확률 하나(유닛 영등 빗나감·영등 ③과 겹쳐도 합산 없음, RNG 한 번). 영웅이 사망·버프 해제 중이거나 차사왕 생존 중이면 꺼지고 지속 시간은 계속 흐른다. 되돌림 없음. 기지 목표는 기존대로 제외
- 일식 반경 600은 영웅 중심, 기지는 제외. 오작교 경직은 비행 적만(어둑시니 대왕은 비행 상태일 때만 대상, 보스 0.5초)이고 소환은 아군 상한을 지킨다(28마리면 2마리)
- 수호 진형·태양 오라·순풍은 영웅 중심 오라형(영웅 사망·해제 중·차사왕 생존 중 꺼짐). 쇠 갑옷·길조는 시간제 버프

### 최종 단계 (12단계)
- 빌드 화면에서 강림·귀문개방은 4단 아래 줄(5단 위치, 이름표 없음)에 표시
- 신명 구매: 1회 100 엽전 고정, 최대 50회(`SINMYEONG_PURCHASE = { price, maxPurchases }`, 기존 basePrice·priceStep 제거). `purchasePrice(n)`은 n을 무시. 저장 보정 상한도 50(필드 변경 없음). 빌드 화면 구매 버튼은 `wallet.nextPrice()`라 100 고정
- 노드 id: `descent`(강림, 무당 트리, tier 4 표시용, 비용 40, 최대 1), `ghostGate`(귀문개방, 연계 트리, tier 4, 비용 1, 최대 1). 노드 필드 `finalStage: 'possession' | 'descent' | 'ghostGate'`가 최종 단계 표시. 빙의 10개 + 강림 + 귀문개방이 배타 그룹 `finalStage`(`FINAL_STAGE_GROUP`, 기존 `POSSESSION_GROUP`은 같은 값의 별칭)
- 수치는 `src/data/finalStage.ts`: `DESCENT_TUNING`(비용 40, 체력·피해·신력 충전 ×3, 쿨타임 0.1/1/5, Q 신력 0), `GHOST_GATE_TUNING`(비용 1, 요괴 5종, 소환 비용 10, 쿨타임 ×0.5)
- 해금 판정 `Build.finalStageFailure(node)`: 빙의 = 무당 완료, 강림 = 무당 완료 → 살림 완료, 귀문개방 = ①②③ 모두 찍은 요괴 5종 이상 → 연계 완료. 강림·귀문개방은 `isTreeComplete`에서 제외(자기 참조 방지). 실패 사유 `salimIncomplete`·`yeongyeIncomplete`·`yogoeUnitsIncomplete`, 순서는 최대 레벨 → 단 → 선행 → 최종 단계 조건 → 배타 → 신명 부족
- 트리 단 해금 기준(5/12/20)은 최종 단계 노드에 적용하지 않음(`isNodeTierOpen`). 각 트리를 다 찍었다면 기준은 이미 충족이라 결과 차이는 없음
- 빼기 제한: 최종 단계 노드의 해금 조건이 깨지면 거부(`prerequisiteDependency`, 의존 = 그 노드). 귀문개방은 "빼고 난 뒤에도 5종 이상이면 허용"(6종 이상이면 일부 가능). 초기화는 언제든 가능. 저장 검증(`isValid`)도 같은 조건을 봄
- "???" 숨김: 최종 단계 조건(신명 제외)을 채울 때까지 `isRevealed` false. 빙의는 기존대로 그 유닛 ①②③ + 무당 완료
- 배타 거부 문구는 일반화: "이미 최종 단계("○○")를 골랐습니다. 최종 단계는 하나만 고를 수 있습니다"(기존 빙의 전용 문구 대체)
- 비용 합계: `allUpgradesTotalCost()`(배타 그룹을 트리와 관계없이 하나만) = 248 그대로. `treeTotalCost`는 트리 안에서만 그룹을 세므로 무당 71·연계 47로 바뀌고 트리별 합의 합은 289(겹침). 테스트 모드 신명 +300은 248 이상이라 그대로 충분
- 전투 보정: `BattleModifiers.hero.descent`·`ghostGate`(boolean), 수치는 `Battle`이 tuning을 읽어 적용. `computeBuildEffects`는 `?upg=`로 여럿이 들어오면 빙의 > 강림 > 귀문개방 순으로 하나만 켬. 계산은 `src/battle/finalStage.ts`(Battle·툴팁 공용)
- 강림: `summon`이 `'descent'` 반환(부적·쿨타임 안 씀, 키·버튼 모두 무시). 최대 체력 = 300 × (단단한 몸 배율) × 3, 신력 충전 = 5 × 신력 샘 × 3, 쿨타임 고정값이 신내림보다 우선, Q 신력 0(빙의와 배타라 빙의 값과 충돌 없음). 피해 ×3은 `resolveHit`에서 `info.source === 'hero'`면 기준 피해에 곱함(상성·방어 파괴 전) — 기본 공격·충격파·스킬 3종·칼날 춤 지속 피해 포함, 회복 태그 대상의 회복량 기준도 같은 값. 영웅 머리 위 이름표 "강림"(빙의 이름표 재사용), 소환 버튼은 "강림" 표시로 비활성
